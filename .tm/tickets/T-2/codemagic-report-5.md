# wrangler-compose から Codemagic へアプリを登録できるか(依頼 I-2 / T-2)

2026-10-30 調査(同日、C-7「グループも削除」と C-8「1 環境 1 アプリ」・C-9「グループは設定に従う」・C-10「--purge は再構築できるかで分ける」を反映して改版)。コードと仕様書は変えていない。

## 結論

**条件付きでできる。** Codemagic へのアプリの登録と、ビルドに要る値(変数グループ)の登録は、Codemagic の API で行え、本物で確かめた。条件は次の 3 つ。

- wrangler-compose の定義を Cloudflare の外へ広げる(Q-9 で決定済み)
- アプリの登録に使う API は Codemagic が「試行版」としているもので、予告なく変わりうる
- 利用者は、Codemagic と GitHub の連携(Codemagic の画面)と、API トークンの用意を最初に 1 回、手で行う

本物で、`.env.production` の値だけから、使っているアプリと同じ変数の設定(7 グループ・21 変数)を作れることを、書き込まずに読み比べて確かめた(下の 7)。

## 1. 登録の手段

| 手段 | できること | 出典・確かめ |
|---|---|---|
| REST API(古い版) `POST https://api.codemagic.io/apps` | リポジトリの URL(と任意でチーム ID)でアプリを登録。返り値はアプリの ID と名前 | [Applications API](https://docs.codemagic.io/rest-api/applications/)。本物で 200 |
| REST API(古い版) `POST /apps/new` | 非公開のリポジトリを SSH の秘密鍵で登録(`projectType: flutter-app` も渡せる) | 同上。本物では試していない |
| REST API(古い版) `GET /apps` | アプリの一覧。リポジトリの URL・設定の出どころ(`settingsSource`)・持ち主のチームも返る | 本物で確認 |
| REST API(古い版) `DELETE /apps/{id}` | アプリの削除 | **公式の資料に無い**。本物で 202 を返し、一覧から消えた |
| REST API(v3) | 変数グループの作成・一覧・削除、変数の一括登録・更新・削除、アプリの一覧(名前で絞れる)、ビルドの開始 | [v3 schema](https://codemagic.io/api/v3/schema)。本物で確認(ビルドの開始は試していない) |
| CLI(codemagic-cli-tools) | ビルドの中で使う道具(署名・ストアへの提出など)だけ。アプリの登録や変数を扱うコマンドは無い | [cli-tools](https://github.com/codemagic-ci-cd/cli-tools) |

v3 の API にアプリの登録は無い。登録だけは古い試行版の API に頼ることになる。

## 2. 登録に要るもの・登録後にできること

- **API トークン:** 利用者個人のもの。Codemagic の画面(Teams > Personal Account > Integrations > Codemagic API)で見る。できることはチームでの役割で決まる。本物では、アプリの読み・更新・削除と、変数の読み・作成・更新・削除の権限があった
- **リポジトリへの接続:** Codemagic の GitHub App を入れておけば、HTTPS の URL だけで非公開のリポジトリも登録できた。入れていなければ SSH 鍵を渡す(`POST /apps/new`)
- **登録しただけの状態:** 設定の出どころは `codemagic.yaml`(`settingsSource: file`)になった。プロジェクトの種類・ブランチ・ワークフローは空(ビルドしたことのあるアプリでは埋まっている。最初のビルドで埋まるかは未確認)
- **同じものの登録:** 同じリポジトリを何度でも登録でき、同じ名前のアプリが並ぶ。名前や URL では 1 つに決められないので、アプリの ID で見分ける
- **変数:** 変数ごとに Secure(秘密)を付けられる。**Secure の値は API でも読み返せない**(null が返る)。秘密でない値は読める
- **ビルドの開始:** v3 にある(`POST /api/v3/apps/{app_id}/builds`)。今回は含めない(決定)

## 3. 料金・プランと API の制限

- API は 1 時間に 5,000 回まで。超えると 429
- Personal Account では、チームで共有する変数グループ(`/teams/{id}/variable-groups`)が使えなかった(404)。アプリごとのグループは使えた
- 料金のプランごとの API の違いは、公式の資料では確かめていない

## 4. wrangler-compose に入れる形

### 決まったこと

| 項目 | 決まり | 出どころ |
|---|---|---|
| 役目 | Cloudflare への展開に加えて、Codemagic へのアプリの登録と値の登録を行う | Q-9 |
| 範囲 | アプリの登録と変数グループまで。ビルドの開始は含めない | I-2 の C-1・C-4 |
| アプリの見分け方 | 登録したアプリの ID を `.env.<環境>` の `CODEMAGIC_APP_ID` に書き足し、次からはその ID のアプリを使う | C-3 |
| 環境とアプリ | **1 つの環境に 1 つの Codemagic のアプリ**。`CODEMAGIC_APP_ID` は `.env.<環境>` にあるので、環境ごとに別のアプリを指す。グループの名前は環境によらず同じに書き、中の値は `.env.<環境>` から入る(環境の違いは `.env` の値だけで表す) | C-3・C-8 |
| トークン | `CODEMAGIC_API_TOKEN` を、ほかの値と同じく環境変数か `.env.<環境>` から読む | Q-10 |
| 入れる値 | compose ファイルに、グループごとに `environment`(秘密でない値)と `secrets`(Secure にする値)を Worker と同じ書き方で書き出す。書いたものだけが Codemagic へ出る | Q-11 |
| 秘密でない値 | `.env` と違えば更新し、同じなら何もしない | C-6 |
| シークレット | 無いときだけ作る。既にあるものは `--update-secret` を付けたときだけ上書きする。Codemagic と Worker(リモート)で同じ決まりにする | C-5・C-6 |
| 手元のシークレット | 手元(`--env local`)では、これまでどおり毎回 `.env.local` の値を使う | Q-12 |
| compose に書いたグループの中の、書いていない変数 | 消す | C-6 |
| compose に書いていないグループ | 消す。Codemagic のグループは compose ファイルの設定に従う(書いたものだけがあり、書いたとおりの中身になる)。対象はその環境の `CODEMAGIC_APP_ID` のアプリのグループだけ | C-5 を C-7・C-9 で改めた |
| アプリを消すとき | アプリもグループも `up` で再構築できるので、`down` で消す(`--purge` は再構築できないものを消す印なので、Codemagic には効き目が変わらない)。グループを先に消してからアプリを消し、`.env.<環境>` の `CODEMAGIC_APP_ID` も消す。リモートの `down` と同じく環境名の打ち直しで確かめる。アプリと一緒に Codemagic のビルドの履歴と成果物も消える(wrangler-compose が作ったものではない) | C-9・C-10 |

### 書き方の例(仮。形は下の「決めること」の D1)

```yaml
services:
  mobile:
    type: codemagic
    groups:
      app_store_connect:
        environment: [APP_STORE_CONNECT_KEY_ID]
        secrets: [APP_STORE_CONNECT_PRIVATE_KEY]
      store:
        environment:
          STORE_DOMAIN: ${DELIVERY_DOMAIN}   # 名前を変えて入れる
        secrets:
          STORE_APP_KEY: ${APP_KEY_PUBLIC}
```

### `up` の流れ(案)

1. `CODEMAGIC_APP_ID` が無ければアプリを登録し、ID を `.env.<環境>` に書き足す(書き足したことと、控えを更新するよう知らせる)
2. グループごとに、無ければ作る
3. 秘密でない値: 違えば更新、無ければ作る
4. シークレット: 無ければ作る。あれば `--update-secret` のときだけ上書きし、無いときは「既にあるので変えていない」と知らせる
5. compose に書いたグループの中の、書いていない変数を消す
6. compose ファイルに書いていないグループを消す(そのアプリのものだけ)

`--dry-run up` は上の計画を示し、何も変えない。シークレットの値は比べられないので、「既にある/無い」だけを示す。

### 名前の付け方との関係

Codemagic のアプリ名はリポジトリの名前から決まり、`<プロジェクト>--<環境>--<名前>` を付けられない。グループの名前は `codemagic.yaml` が名指しで読むので、利用者が書いた名前をそのまま使う。持ち主は名前ではなく、その環境の `.env.<環境>` の `CODEMAGIC_APP_ID` のアプリかどうかで決める。グループの名前に環境の名前を入れない(環境の違いはアプリと `.env` の値で表す)。

### 試して分かった事故の元

- **アプリを先に消すと、そのアプリのグループが消せずに残る。** 試験で作ったアプリを消したところ、5 つのグループ(中身は本物の秘密)が残り、グループの削除も中の変数の一覧も 500 になった。今もある(ID 末尾 0613・0617・061b・0623・0625)。消すときは、グループを先に消してからアプリを消す。残ったものは Codemagic のサポートに頼む必要がある
- **同じリポジトリで何度でも登録できる。** ID が無い環境で `up` すると、2 つ目のアプリができる(D3)

## 5. 要求仕様とのかね合い(改める箇所)

| 箇所 | いま | 改める内容 |
|---|---|---|
| 決定と用語の「定義」 | Cloudflare へ展開するもの。使える API は wrangler login で付与されるものだけ | Codemagic へのアプリの登録と値の登録を足す。使える API に Codemagic の API を足す(Q-9) |
| REQ-002 サービスの型 | worker・d1・r2・kv・queue | Codemagic の型を足す(D1) |
| REQ-004 環境ごとの値 | — | `CODEMAGIC_APP_ID`・`CODEMAGIC_API_TOKEN` の読み方。`CODEMAGIC_APP_ID` は道具が書き足す |
| REQ-005 シークレット | `up` のたびに入れる | 無いときだけ作り、`--update-secret` で上書き(リモート)。手元は毎回 |
| REQ-015 安全 | 消すものを示して打ち直し・シークレットを画面に出さない | Codemagic の値も画面・ログに出さない。グループと変数を消すときの確かめ方(D6) |
| REQ-016 手で行う段取り | 人が行うのは Cloudflare へのログインを 1 度だけ | 加えて、Codemagic の API トークンの用意と、Codemagic と GitHub の連携を 1 度だけ |
| 範囲外 | Wrangler のコマンドでも Cloudflare の API でも行えない操作 | 「Codemagic の API で行えるもの」を除く。ビルドの開始は範囲外 |
| README | Cloudflare Workers の環境を docker compose のように扱う | Codemagic を扱うことを書き足す |
| コマンド | `up` などに `--update-secret` は無い | `--update-secret` を足す(docker compose に無いものを足す利用者の決定) |

## 6. API トークンと REQ-015

満たせる。トークンも Codemagic に入れる値も、画面・ログ・`--dry-run` に出さない(名前と、値があるかどうかだけを出す)。`.env.<環境>` は git に入らない決まり(REQ-004)がそのまま効く。`.env` をチームで共有する場合はトークンも共有されるが、これは使う側の選択(Q-10)。

## 7. 本物で確かめたこと

使った場所: 利用者の Codemagic の Personal Account。試験用に、同じリポジトリのアプリを 1 つ登録し、消した。既にあるアプリには書き込んでいない。

| 確かめたこと | 結果 |
|---|---|
| トークンで読めるもの | 利用者・チーム・権限・アプリ・グループ・変数 |
| Secure の値を読めるか | 読めない(null) |
| 同じリポジトリの 2 回目の登録 | できた(別の ID・同じ名前) |
| 登録直後の設定の出どころ | `codemagic.yaml`(file) |
| グループの作成・変数の一括登録 | 5 グループ・15 変数ですべて 201 |
| 既存と新しいアプリの読み比べ | グループ・変数の名前・Secure の有無がすべて一致。秘密でない値も、元の `.env` と違っていた 1 つを除き一致 |
| アプリの削除 | 202。ただしグループが残った(4 の事故の元) |
| `.env.production` からのシミュレーション(書き込みなし) | 7 グループ・21 変数がすべて作れる。ふつうの `up` では書き込み 1 件(違っていた秘密でない値の更新)だけ |

確かめていないこと: `POST /apps/new`(SSH 鍵)、ビルドの開始、新しく登録したアプリが実際にビルドできるか(プロジェクトの種類などが最初のビルドで埋まるか)、Secure の値が正しいか(読み返せないため)。

## 決めること(まだ決まっていない)

| | 問い | 推奨 |
|---|---|---|
| D1 | compose ファイルにどう書くか: サービスの型(`type: codemagic`)にするか、一番上に別のキーを置くか | サービスの型。「1 つのサービスは 1 つの資源」と同じ形で、名前の決まり・`x-` の読み飛ばし・誤りの示し方をそのまま使える |
| D2 | 登録するリポジトリの URL をどこから取るか: compose ファイルに書くか、git の `origin` から取るか | compose ファイルに書く。PC によって `origin` の書き方(SSH・HTTPS)が違いうるため |
| D3 | `CODEMAGIC_APP_ID` が無い環境の初めての `up` | その環境のアプリを新しく登録する(同じリポジトリのアプリが既にあっても、それはほかの環境のもの)。環境名の打ち間違いでアプリが増えないよう、REQ-015 の初めての環境と同じく、示して確かめる。アプリ名はリポジトリの名前になり環境どうしで同じになるので、見分けたいときは利用者が画面で名前を直す(C-2) |
| D4 | 手元(`--env local`)で Codemagic のサービスをどう扱うか | 何もしない。手元では何もしないことを知らせる(REQ-018 と同じ) |
| D6 | 初めての登録と、グループ・変数を消すときに確かめるか | どちらも、何をするかを示して環境名の打ち直しで確かめる(REQ-015 の初めての環境・消す操作と同じ)。Codemagic の画面で人が足したグループも消えるので、確かめが要る |
| D7 | 値が空の変数 | 入れない。既に Codemagic にあれば、書いていない変数と同じく消す |
| D8 | `ps` で何を示すか | アプリ(ID・名前・リポジトリ)と、グループごとの変数の名前・Secure の有無・値があるか |

## チケットの分け方(案)

1. **要求仕様を改める:** 上の 5 の箇所と、D1〜D8 の決定。受け入れ条件も足す
2. **詳細仕様:** 使う API と順序(グループを先に消してからアプリ)、`CODEMAGIC_APP_ID` の書き足し方、`--dry-run` の示し方
3. **Worker のシークレットの `--update-secret`(Cloudflare 側):** Codemagic と切り離して先に作れる
4. **Codemagic の型の実装:** 登録・ID の書き足し・グループと変数の同期・`--dry-run`・`ps`
5. **本物での受け入れ確認:** 試験用のアプリで、登録から片づけまで(片づけはグループを先に消す)
6. **(利用者)残った 5 つのグループの片づけ:** Codemagic のサポートへの依頼
