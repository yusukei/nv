wrangler-compose 受け入れ条件

確かめは、試験用の Cloudflare アカウントの使い捨ての環境(Worker・D1・R2)で行う。本番の環境では行わない。Windows x64 と macOS arm64 の両方で確かめる。

AC-001環境の指定 REQ-001

  • --env staging up・-e staging up・CLOUDFLARE_ENV=staging を付けた up が、同じ環境に同じ結果を出す。--env と CLOUDFLARE_ENV の両方を付けたら --env の環境に出る
  • 環境を指定せずに up・down・backup・restore を打つと、Cloudflare に何も起きずに止まり、環境の指定が要ると出る
  • 設定に無い環境名(設定の環境名の略や別名を含む)を指定すると、何も起きずに止まり、設定にある環境名が並ぶ

AC-002設定の持ち主と Wrangler の呼び方 REQ-002

  • wrangler-compose のリポジトリと、使う側のプロジェクトに、Wrangler の設定ファイル以外の環境の定義が無い
  • wrangler-compose が動かす Wrangler の版が、プロジェクトの package-lock.json の版と一致する(PATH にほかの版の Wrangler や nv があっても。使う nv は wrangler-compose と同じフォルダのもの)
  • どの操作のあとも、プロジェクトのファイルが変わっていない(git status に差分が出ない)。D1・R2 を新しく作った up を端末から打ったときも同じ
  • 同じフォルダに nv が無い、またはプロジェクトの依存に Wrangler が無いと、何も起きずに止まり、入れ方が出る
  • プロジェクトの Wrangler が要る版より古いと、何も起きずに止まり、要る版が出る

AC-003build REQ-003

  • --env staging build のあと、Cloudflare の Worker・D1・R2 が変わっていない
  • 設定のビルドのコマンドが失敗すると、build も失敗し、理由が出る

AC-004up REQ-004

  • まだ何も無い環境(D1 を名前だけで書いた設定)に up を打つと、Worker・D1・R2 ができ、D1 にすべての移行が当たり、Worker の URL が応える
  • D1 がすべてある環境で、移行を 1 つ足して up を打つと、足した移行だけが当たり、新しいコードが出る。確認を求められない
  • D1 がすべてある環境で、失敗する移行を足して up を打つと、デプロイは行われず(前のコードのまま)、どの移行で止まったかが出る
  • まだ無い D1 がある環境で、失敗する移行を入れて up を打つと、デプロイは済み、移行が当たっていないことと、どの移行で止まったかが出る
  • 設定に database_id を書いた D1 が無いと、up は何もデプロイせずに止まり、その D1 の名前と ID が出る
  • .env.staging があると、up のあと、そこに書いたシークレットが Worker に入っている。WRANGLER_COMPOSE_ で始まる値は入っていない。ファイルが無ければ、前のシークレットのまま
  • .env.staging から 1 つ消して up を打つと、そのシークレットは Worker に残り、その名前が示される

AC-005down REQ-005

  • down を打つと、消す前に、Worker と一緒に消えるもの(シークレット・ルート・カスタムドメイン・Cron・Durable Objects)が出る
  • 環境名を正しく打ち直すと、Worker が無くなり、D1 の表の中身と R2 のオブジェクトは変わらない
  • 打ち直した名前が違うと、何も消えない
  • 入力を流し込んで(echo staging | wrangler-compose --env staging down など)打つと、何も消えずに止まる
  • down のあと up を打つと、Worker が戻り、down の前と同じ D1・R2 の中身が見える

AC-006down --purge REQ-006

  • 正しい API キーを渡して down --purge で環境名を打ち直すと、Worker・D1・R2 バケットが無くなる(オブジェクトのあるバケットも)
  • API キーを渡さない・誤ったキーを渡すと、警告が出て、Worker・D1・R2 はどれも変わらない
  • 消す前に、Worker 名・D1 の名前・バケットの名前とオブジェクトの数が出る
  • 入力を流し込んで打つと、何も消えずに止まる
  • 設定に database_id を書いた D1 があると、消す前に、消したあとの up がその D1 を作り直さないことが出る
  • 名前だけで書いた設定の環境を down --purge したあと up を打つと、空の D1・R2 が新しくでき、移行が当たる
  • 途中で止めると(網を切るなど)、何を消して何が残っているかが出る

AC-007backup REQ-007

  • backup のあと、プロジェクトの backups/<環境名>/<日時>/ に、D1 の SQL(移行の履歴を含む)・R2 のすべてのオブジェクト・目録がある。オブジェクトの数と大きさが環境と一致する
  • backup <別のフォルダ> を打つと、そのフォルダの <環境名>/<日時>/ に同じものができ、プロジェクトの backups/ には何もできない
  • git の中のプロジェクトで backups/ が .gitignore で外れていないと、何も書き出されずに止まる。git の外の書き出し先なら止まらない
  • API キーを渡さない・誤ったキーを渡すと、警告が出て、書き出し先に何もできない
  • 書き出しの途中で止めると、残ったフォルダは書きかけと分かり、restore に渡すと止まる
  • 書き出せない表を持つ D1 があると、その D1 と理由が出て止まり、完成した控えはできない

AC-008restore REQ-008

  • 別の環境に up したあと、AC-007 の控えを restore --drop して環境名を打ち直すと、D1 の表の中身と R2 のオブジェクト(キー・中身・内容の種類)が控えと一致する。up でできていたオブジェクトや行は残らない
  • 控えを取ったあとに移行を 1 つ足したコードで、上と同じことをすると、戻したあとに足した移行だけが当たり、Worker が応える
  • --drop を付けずに、中身のある(up で移行が当たった)戻す先へ restore すると、何も変わらずに止まり、空でないものと --drop のことが出る
  • restore --drop を打つと、消す前に、D1 ごとの表の数とバケットごとのオブジェクトの数と、戻している間に欠けたデータが見えることが出る。打ち直した名前が違う、または入力を流し込んで打つと、何も変わらずに止まる
  • 戻す先の D1・バケットが無いと、何も変わらずに止まり、先に up を打つよう出る
  • 書きかけの控え、または移行の履歴の入っていない控えを指定すると、何も変わらずに止まる
  • API キーを渡さない・誤ったキーを渡すと、警告が出て、何も変わらない(--drop でも)
  • 途中で止めると、何を消し、何を入れて、何が残っているかが出る

AC-009秘密の扱い REQ-009

  • up・down・down --purge・backup・restore のどれでも、画面・ログ・目録に、API キーとシークレットの値が出ない(失敗したときの出力も含む)
  • .env.staging と環境変数に別の API キーを入れると、環境変数のキーが使われる
  • アカウント ID や管轄を .env.staging に書かなくても、backup が動く
  • git の中のプロジェクトで、.env.staging が .gitignore で外れていない、またはすでに git に入っていると、up・down --purge・backup・restore は何も起きずに止まる。git の外のプロジェクトでは止まらない

AC-010配り方と更新 REQ-010

  • Node も npm も入っていない Windows と macOS で、同じフォルダに置いた wrangler-compose と nv の実行ファイルだけで、up が動く(Node と Wrangler は nv が揃える)
  • 版のタグを push すると、その版の GitHub の Release に、nv と並んで OS ごとの wrangler-compose の実行ファイルと検証値が並ぶ
  • wrangler-compose self update・wrangler-compose install skill は無い。更新とスキルは nv の AC-010・AC-008 で確かめる

AC-011dry-run REQ-011

  • --dry-run up のあと、Worker の版・D1 の移行の履歴・シークレット・設定ファイルが変わっていない。当てる予定の移行の名前と、入れる予定のシークレットの名前(値は出ない)が出る
  • --dry-run down・--dry-run down --purge のあと、Worker・D1・R2 はどれも変わっていない。消す予定のもの(--purge ならオブジェクトの数まで)が出る。端末でなくても(入力を流し込んでも)動く
  • --dry-run backup のあと、書き出し先に何もできていない。書き出す D1 とバケットとオブジェクトの数が出る
  • --dry-run restore --drop のあと、D1 と R2 の中身が変わっていない。消す予定のものと戻す予定のものが出る
  • 本番の操作が止まる条件(.env が git に入っている、API キーが無い、書きかけの控え、など)では、dry-run も同じに止まる
  • どの dry-run も、終わりに何も変えていないことが出る

AC-012表示の言語 REQ-012

  • OS の言語が日本語の PC で、--env を付けずに up を打つと日本語のエラーが出る。--dry-run up の示す内容と --help の説明も日本語
  • NV_LANG=en を付けると英語で出る
  • 日本語の表示でも、down の確かめで環境名(例: testing)を打てば進む
