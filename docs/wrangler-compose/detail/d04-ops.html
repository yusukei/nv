wrangler-compose 詳細仕様

D04. down・ps・logs・backup・restore・dry-run

下ろす・見る・バックアップする・戻す・確かめる。DES-012〜015。

設計

DES-012down REQ-011

  • リモート: 依存の逆の順に delete。--purge なら、D1 は d1 delete、R2 はデータのサービスで空にしてから r2 bucket delete、KV は kv namespace delete、Queue は queues delete。下ろさないサービスがつながる資源があれば何も消さずに止まる
  • リモートでは消す前に中身を数えない(名前だけを示す)。打ち直しは 0.1 系のものを引き継ぐ
  • 手元: down は動いている up を止める。down web のように名前を付けると、動いている up がその Worker を外して動かし直し、ほかは動き続ける(データのサービスは手元では止めるものが無い)。下ろした Worker は、もう一度 up(up web)を打つと動いている up に戻る。下ろしたものが無いときの 2 つ目の up は止まる。--purge は止めたあと .wrangler/compose/local/state を消す。サービスを名前で指すと、そのサービスの資源とつなぐ資源(Durable Object の保存先を含む)だけを空にし、名前に無い Worker もつながる資源があれば、何も止めず何も消さずに止まる

DES-013ps・logs REQ-012

  • ps(リモート): Worker・資源は DES-004 の一覧、未適用の移行は D1 の履歴の表を API で SELECT で読む。compose に無い Worker は「残り」として出す。手元: 動いている記録と URL
  • logs(リモート): Worker ごとに wrangler tail --format json を並べて動かし、サービス名 | を頭に付けて出す(手元の受け手と同じ形)。過去のログは読めないので、-f が無くても今から追う。手元: up が書く .wrangler/compose/local/logs/up.log を読む(-f なら追う)

backup・restore の受け渡し

DES-014backup・restore REQ-013

  • 手元は、D1・R2・KV のどれも、データのサービスで、その環境の中から書き出し・読み込む(手元で up が動いている最中に別のプロセスから D1 を書き出す・戻すと、同時の書き込みで失敗するため。SQLITE_BUSY。実測)。リモートは、Wrangler 自身がログインの資格で呼ぶ Cloudflare の API で読み書きする(D1 は /raw と /query。値を SQL に書き込んだ文をまとめて 1 回で送り、D1 は 1 つの batch として実行する。KV は keys・values・metadata・bulk。R2 はオブジェクトの一覧・取得・書き込み・消去)。どちらも、名前がその環境のもの(REQ-006)だけを扱い、まだ無いものがあれば先に up するよう示して止まる。道具はバックアップのファイルとの受け渡しだけを行う
  • バックアップの形(format: 3。環境によらず同じ): manifest.json(最後に書く。無いフォルダは書きかけ)に project・environment・created・資源ごとの type・key・ファイルと SHA-256。D1 は d1/<key>.jsonl(表の作り・行・索引など。1 行 1 つの JSON。BLOB は base64)、R2 は r2/<key>/ にオブジェクトとメタデータ、KV は kv/<key>.jsonl(キー・値(base64)・メタデータ・期限)
  • 戻すときは、資源の名前と型で compose ファイルに照らし、すべてのファイルの SHA-256 を確かめてから始める。D1 は表の作り → 行(50 行ずつ。外部キーは確かめを後回しにする)→ 索引などの順に入れ、最後にバックアップのあとの移行を当てる(移行の SQL の分け方は Wrangler の unstable_splitSqlQuery)。KV は戻す時点で期限が切れたものを戻さない
  • D1 は、すべての表と AUTOINCREMENT の数え(sqlite_sequence)を 1 つの batch(1 つのトランザクション)で読むので、up が動いている最中のバックアップも 1 つの時点のものになる。生成列は書き出さない(入れるときに計算し直される)。整数の主キーを持たない表は、隠れた rowid も残す
  • JSON では正しく運べない値(2^53 を超える整数、整数に見える実数・無限大、印の文字で始まる文字列、BLOB(16 進で書き、戻すときに unhex))は、印(文字コード 1)を付けた文字列で書き、戻すときに CAST で元の型に戻す
  • restore --drop は消す前にいまの中身を .wrangler/compose/<環境>/before-restore/ にバックアップし、途中で失敗すれば消してバックアップを戻す(成功すればバックアップは消す)。空の先への restore が失敗したときは空に戻す
  • D1 の仮想表(FTS など)はバックアップできない(止まって示す)
  • 手元で up が動いていなければ、操作の間だけ入口とデータのサービスだけの実行環境を立てる

DES-015dry-run と確かめ REQ-014・REQ-015

  • どの操作も「確かめ → することの一覧を作る → 変える」の 3 段にし、--dry-run は 2 段目で一覧を示して終わる(止まる条件を本番と別に書かない)
  • 消すものを含む一覧は、変える前に環境名の打ち直しで確かめる(端末でなければ止まる)
  • リモートの up の一覧は terraform plan の形にする: 2 段目で Cloudflare にいまある値を読み(資源の一覧・バケットの設定・Worker の設定(bindings・environment・互換日付)・スケジュール(crons)・経路(routes)・シークレットの名前・版の印・D1 の移行の履歴)、compose ファイルから作る値と比べて、+ 作る・~ 変える(項目ごとに前と後)・- 消す・= 変わらない、と数を示す。--dry-run はここで終わる。up は確かめを求めずに 3 段目に進む(初めての環境と消すものがあるときの打ち直しは今までどおり)
  • コードの違い: 展開のときに組み立てたもののハッシュを Worker の版の印(wrangler deploy --tag)に入れ、次の一覧で読み戻して比べる。この PC の記録には頼らないので、どの PC からでも同じ結果になる。シークレットは Cloudflare が値を返さないので、名前の増減だけを比べる
