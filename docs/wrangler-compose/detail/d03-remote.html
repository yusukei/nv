DES-009リモートの up REQ-010・REQ-005・REQ-015

  • 段: 組み立て(DES-007。Cloudflare に触れる前) → いまの Cloudflare を引く(DES-004) → 確かめ(初めての環境・--purge で消す資源があれば、まとめて示して環境名の打ち直し。消える Durable Object のクラスと、Durable Object を持つ消える Worker は、消す・残す・やめるを選ばせる) → 無い資源を作る → バケットの設定(DES-018) → サービスの順に: D1 の移行(d1 migrations apply --remote)、Worker を作った設定と --secrets-file(0600 の一時ファイル)で上げ、compose から消えたシークレットと、受け取らなくなった Queue の受け手を消す
  • 作る設定: 組み立てたものをそのまま(no_bundle。横のファイルも ES モジュールとして)、バインディングは実際の名前と ID、Queue の受け手は Cloudflare の既定値、routes は / か * を含めばルート、含まなければ独自ドメイン。workers.dev の URL は、ports を持ち(外から呼ばれる Worker)routes の無い Worker だけに開く(手元で ports の無い Worker はリモートでも外から届かない)。プレビューの URL は開かない
  • 前回と同じ(組み立てたもの・作った設定・シークレットの名前が同じ。DES-023)Worker は上げない。--dry-run は同じ段を通り、変えることを示すだけ(合言葉のファイルも作らない)
  • 移行が失敗したら、その D1 を使う Worker と、それより後のサービスは行わない
  • 名前がこの環境のもので compose に無い Worker は、展開のあとに消す。名前がこの環境のもので compose に無い D1・KV・R2・Queue は示し、--purge のときだけ消す(R2 はオブジェクトの一覧の API で空にしてから消す)

DES-010Durable Objects のクラスの足し引き REQ-002・REQ-015

  • Wrangler の新しい宣言の形(exports。2026-07 から)を使う: compose の durable_objects の各クラスを {"type": "durable-object", "storage": "sqlite"} と宣言し、Cloudflare がいまの名前空間と比べて作る。移行のタグは持たない。古いキー値の保存のクラスは扱わない(利用者の決定 2026-10-13)。手元も同じ宣言を使う
  • Cloudflare に名前空間があり compose から消えたクラスは、クラスごとに消す・残す・やめるを選ばせる(環境名で消す・keep で残す・ほかの入力と空の Enter と端末が無いときはやめる)。消すクラスは {"state": "deleted"} の墓標として宣言して消し、残すクラスは今までどおり宣言する
  • 消すクラスがあれば中身も消えるので、消すものとして示し、環境名の打ち直しで確かめる

DES-018R2 のバケットの設定 REQ-002・REQ-009

  • リモート: up が、バケットごとに compose ファイルの設定と Cloudflare の設定を比べ、違えば合わせる。作るときの storage_class・jurisdiction は r2 bucket create の引数、ほかは r2 bucket dev-url(public)・r2 bucket cors・r2 bucket lifecycle・r2 bucket notification・r2 bucket lock で入れる。compose ファイルから消した設定は消す
  • 手元: Wrangler の手元の模擬に無いもののうち、再現すると決めたもの(CORS・公開の URL・イベント通知)を道具のサービス(DES-011)で効かせる。公開は入口のサービスがバケットの公開の URL を配り、CORS は S3 互換の口と公開の URL の応答に付け、通知はオブジェクトの変化を手元の Queue へ送る。ライフサイクル・ロック・保管の種類は手元では効かせない(REQ-009)
  • 手元で、バインディングからの書き込み・消去(Worker のコードの env.FILES.put など)を道具のサービスが見る手立て(通知・ロックのため)は、作る前に確かめる(確かめていないこと)

DES-021コンテナ(リモート) REQ-020・REQ-010・REQ-014

  • 作る設定に containers を入れ(DES-020 と同じ。絶対パス)、wrangler deploy に任せる。Wrangler は Worker を上げたあと、Dockerfile からイメージを作って Cloudflare のコンテナのレジストリに送り(中身が同じなら送らない)、上げた版の Durable Object の namespace に結び付けてアプリケーションを作る・変え、入れ替えを始める。入れ替えは up のあとも続く(知らせる)
  • アプリケーションの名前は道具が決めて設定の name に書く: <Worker の名前>-<クラス> を小文字にし、続く - を 1 つにまとめ、末尾に <Worker の名前>-<クラス> の SHA-256 の先頭 8 文字を付ける(63 文字まで)。Cloudflare は名前に -- を許さない(2026-10-13 に本物で確かめた: VALIDATE_INPUT ... has two consecutive dashes)。印があるので、a-b と c、a と b-c のようなプロジェクトと環境の組がぶつからない
  • 持ち主: アプリケーションが結び付いた Durable Object の namespace(durable_objects.namespace_id)が、この環境の Worker のクラスのものなら、この環境のもの。namespace がもう無い(クラスを消した後など)ときは、その Worker とクラスから決まる名前で探す。名前の頭だけでは選ばない
  • 変わったかの判定: 版の印(DES-015)には、コンテナを Dockerfile の場所ではなく中身のハッシュ(Dockerfile・ビルドの基点のすべてのファイル・image_vars。レジストリのイメージは参照)で入れる。どの PC から打っても同じ印になる。コンテナごとの中身のハッシュは展開の説明(--message。100 文字まで)に wc-containers <クラス>=<ハッシュ> … の形で残し、plan はそれと比べてイメージが変わるかを示す(説明に無ければ「変わるかもしれない」)。max_instances は Cloudflare のアプリケーションと比べる。instance_type は、Cloudflare が名前ではなく数(configuration.vcpu・memory_mib・disk.size_mb)で返すので、名前を Wrangler の表(lite 0.0625・256MiB・2000MB、basic 0.25・1024・4000、standard-1 0.5・4096・8000、standard-2 1・6144・12000、standard-3 2・8192・16000、standard-4 4・12288・20000)で数に直し、独自の大きさは書いていないキーを Wrangler の既定(0.0625・256・2000)で埋めて比べる
  • 消す: compose ファイルから消したコンテナ(クラスは残る)のアプリケーションは、その Worker を上げる前に消す。消したクラス・compose に無い Worker・down で下ろす Worker のアプリケーションは、Worker を消す前に消す(Cloudflare は Worker を消してもアプリケーションを消さない)。up が消したアプリケーションと同じ名前のリポジトリのイメージは、展開と Worker の削除が済んだあとにレジストリから消す(あとから見つける手掛かりが無くなるため。レジストリの一覧を読めなければ警告して残す)。down(--purge なし)が消すアプリケーションのイメージは残す
  • Docker: Dockerfile のコンテナがあれば、Cloudflare に触れる前に確かめる(--dry-run も)。リモートへのビルドは Windows でもできるので、Windows では止めない
  • コンテナを使えないアカウント: アプリケーションの一覧(/containers/applications)を読めなければ、compose ファイルにコンテナがあるときだけ Cloudflare の答えを示して止まる。無ければ今までどおり
  • ps は、コンテナのアプリケーションがあるかと、compose ファイルに無いもの(次の up が消す)を示す
  • レジストリのイメージ: down --purge は、下ろす Worker のクラス(Cloudflare にあるもの)と compose ファイルのコンテナのクラスから決まるアプリケーションの名前のリポジトリにあるイメージを、wrangler containers images list --json で探し、wrangler containers images delete で消す(消す前に示し、環境名の打ち直しで確かめる)。ほかの名前のリポジトリには触らない。Wrangler はレジストリの一覧と削除を HTTPS でだけ行うので、偽の API の試験では確かめられない(本物で確かめた)
  • イメージを先に送る: up は、Dockerfile のコンテナのリポジトリにイメージが 1 つも無ければ(初めて、または down --purge のあと)、展開の前に、Wrangler と同じ作り方(linux/amd64・provenance なし・image_vars)でイメージを作り、毎回新しいタグ(wc-<中身のハッシュ 8 文字>-<時刻>)で wrangler containers push する。レジストリは消したイメージのダイジェストにも答え続けるので、wrangler deploy は中身の同じイメージを「もうある」として送らず、Cloudflare は「イメージが無い」(IMAGE_REGISTRY_DOESNT_CONTAIN_IMAGE)で止まる。また、消したタグと同じ名前で送り直しても、しばらくは一覧に出ず使えない(どちらも 2026-10-13 に本物で確かめた)

DES-022Codemagic REQ-021・REQ-004・REQ-011・REQ-015

  • 読む: type: codemagic のキーは repository(必須。文字列)と groups(グループの名前 → environment・secrets)。environment・secrets は Worker と同じく対応表にそろえ、secrets に変数を含まない値があれば止める(DES-002)。グループの名前は Codemagic の決まり(. と $ を含まない)に合わなければ止める
  • トークン: リモートで Codemagic のサービスがあるときだけ、CODEMAGIC_API_TOKEN を環境変数 → .env.<環境> から読む(DES-003)。無ければ、Cloudflare にも Codemagic にも触れる前に止め、Codemagic の画面のどこで見るか(Teams > Personal Account > Integrations > Codemagic API)を示す。トークンはヘッダ x-auth-token にだけ入れ、画面・ログ・エラーの文に出さない。送り先は HTTPS だけ
  • 使う API(送り先は https://api.codemagic.io と https://codemagic.io/api/v3): アプリの登録 POST /apps(repositoryUrl)・アプリを読む GET /apps/{id}・アプリを消す DELETE /apps/{id}(公式の資料に無い。本物で 202)・グループの一覧と作成 GET/POST /api/v3/apps/{id}/variable-groups・グループを消す DELETE /api/v3/variable-groups/{gid}・変数の一覧と一括登録 GET/POST /api/v3/variable-groups/{gid}/variables(一括登録は secure ごとに 1 回)・変数を変える・消す PATCH/DELETE /api/v3/variable-groups/{gid}/variables/{vid}。一覧はページを最後まで読む(page_size=100・total_pages)
  • up の段(Cloudflare の段のあとに行う。Cloudflare で止まれば Codemagic に触れない): (1) CODEMAGIC_APP_ID があれば GET /apps/{id} で確かめ、無い(404)なら止めて、.env.<環境> から行を消せば登録し直すと示す。(2) 無ければ、DES-015 の確かめ(初めての環境と同じ打ち直し)のあと POST /apps で登録し、返った _id を .env.<環境> に書き足す。(3) グループと変数を読み、compose ファイルと比べて、グループを作る → 変数を作る・変える → 書いていない変数を消す → 書いていないグループを消す、の順に行う
  • 比べ方: 秘密でない値(environment)は Codemagic の値と比べ、違えば PATCH(値)。Secure の値(secrets)は Codemagic が値を返さない(null)ので、名前があれば変えず、--update-secret のときだけ PATCH(値)。Secure の有無が compose ファイルと違う変数は、PATCH で secure と値を入れ直す。展開した値が空の変数は入れず、あれば消す
  • .env.<環境> の書き換え: CODEMAGIC_APP_ID=<id> の 1 行を末尾に足す(末尾に改行が無ければ先に足す)・down で CODEMAGIC_APP_ID= で始まる行だけを消す。ほかの行と、ファイルの権限はそのまま。同じフォルダの一時ファイルに書いてから入れ替える(途中で止まっても壊さない)。環境変数で CODEMAGIC_APP_ID を渡したときは、それを使い、ファイルは書き換えない
  • down: グループをすべて消してから DELETE /apps/{id} し、CODEMAGIC_APP_ID の行を消す(アプリを先に消すと、そのグループが消せず読めないまま残る。本物で確かめた)。アプリがもう無ければ(404)、行を消すだけにする。消す前に、アプリの ID とグループの名前を示し、ビルドの履歴と成果物も消えることを添えて、環境名の打ち直しで確かめる(DES-012 の打ち直しにまとめる)
  • --dry-run・ps: GET だけを使う。plan は Cloudflare と同じ形(+・~・-・=)で、アプリの登録、グループと変数の作る・変える・消す、Secure の値の「あるので変えない」を示す。値は秘密でないものだけを前後で示す
  • エラー: Codemagic の答えの状態と、本文の message を示して止め、それまでに済んだことを示す(送った値は出さない)。429 は ratelimit-reset の秒数を示して止める。どの段も、もう一度 up すれば揃う(変える前に毎回読み直すので)
  • 手元: --env local では Codemagic に触れず、トークンも読まない。up の初めに、Codemagic のサービスは手元では何もしないと 1 行知らせる

DES-023シークレットの入れ直し(--update-secret) REQ-005・REQ-010・REQ-014

  • リモートの Worker: DES-015 の 2 段目で読むシークレットの名前と比べ、--secrets-file に入れるのは、まだ無い名前だけにする(--update-secret なら compose ファイルのすべて)。deploy --secrets-file はファイルに無いシークレットを消さないので、既にあるものはそのまま残る(確かめた事実)。compose ファイルから消えた名前は今までどおり消す
  • 前回と同じかの判定(DES-009): シークレットは名前の並びだけを入れ、値の要約は入れない(値を変えただけでは上げ直さない)。--update-secret のときは、シークレットのある Worker を必ず上げる
  • 入れ直さなかった名前があれば、up の終わりに Worker ごとに名前を並べ、値を変えたなら --update-secret を付けるよう 1 度だけ知らせる。--dry-run にも同じことを示す
  • 手元(--env local): 今までどおり毎回 .env.local の値を入れる。--update-secret は受けて、何もしない
