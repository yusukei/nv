wrangler-compose 詳細仕様

D05. 引き継ぎ・試験・確かめていないこと

0.1 系から引き継ぐもの、試験の分け方、作る前・受け入れの前に確かめること。DES-016・017。

設計

DES-0160.1 系から引き継ぐもの

  • 引き継ぐ: .env の読み・git の確かめ・打ち直しの確かめ・止め方・表示の言語・D1 の書き出しと戻しと履歴の表の読み・バックアップの目録と書きかけの扱い
  • 作り直す: 設定の読み方(compose ファイルから作る)・up・down・restore・コマンド
  • 捨てる: S3 互換の API で R2 を扱う部分(データのサービスに置き換える)
  • 0.1 系の使い方との互換は持たない。版は 0.2.0

DES-017試験

  • 単体: compose ファイルの確かめ・値の展開・サービスの順・作る設定・Worker のフォルダの確かめ・Durable Objects のクラスの宣言・バックアップの目録
  • 試験だけのための環境変数(利用者向けの README・要求には書かない。利用者の決定 2026-10-13): WRANGLER_COMPOSE_NV(同じフォルダ以外の nv を使う)・CLOUDFLARE_API_BASE_URL(Cloudflare の API の送り先を偽の API に向ける)。nv の NV_HOME は nv の設計(DES-002)に書く
  • 手元の結合(CI。3 つの OS): 受け入れ条件の試験用のプロジェクトで、手元の AC(AC-003・AC-005・AC-008・AC-009・AC-013 の手元の分など)を動かす
  • リモートの流れ(CI。Linux): 偽の Cloudflare の API(tests/fake-cloudflare.py。CLOUDFLARE_API_BASE_URL で道具と Wrangler の両方を向ける)に対し、新しい環境の up(打ち直しを含む)・2 回目は何も上げない・シークレット/受け手/クラスを消す・移行の失敗で止まる・残りの Worker・ps・down web・down を通す。道具の段を確かめるもので、Cloudflare の本当の振る舞いではない
  • リモートの本物: 試験用のアカウントで、利用者の許可を得てから。まず --dry-run で全操作を通す

確かめていないこと(作る前・受け入れの前に確かめる)

  • リモートのすべて(本物の Cloudflare では一度も動かしていない。偽の API と、Cloudflare の公開の API 定義・Wrangler 4.149.0 の作りに合わせて書いた): 資源の作成と設定の答えの形、R2 の設定の比べ方(Cloudflare が足す既定の値で毎回「違う」とならないか)、exports での Durable Object のクラスの作成と墓標、Queue の受け手の付け外し、wrangler auth token の資格で各 API が通るか(ログインの権限の範囲)、wrangler tail --format json の出し方、データのサービスへの合言葉の入れ直しが効くまでの時間
  • 組み立てたものを組み直さずに使えること(deploy --no-bundle でのリモートの展開、wrangler dev での手元の実行と、コードが変わったときの組み直し)
  • 入口と中継を通しても、WebSocket・大きな本体・Server-Sent Events が届くこと
  • 手元のログから、どの Worker の行かを見分けられること
  • リモートの backup・restore と --purge: R2 のオブジェクトの一覧の API(/r2/buckets/<名前>/objects。Wrangler 自身は使っていない)がログインの資格で呼べること。使えなければ、R2 の backup・restore・空にすることは止まる。R2 のオブジェクトの独自のメタデータ(customMetadata)は、リモートでは書き出し・戻しをしていない(API での渡し方を確かめていない)。D1 の /raw に複数の文を送ったときの答えの形
  • plan: Worker の設定(/settings)・cron(/schedules)・版の印(/deployments と /versions/<ID> の workers/tag)を、本物が偽の API と同じ形で返すこと
  • 前回展開した Durable Object のクラスの一覧を Cloudflare から読めること
  • Windows で、中継・錠・止め方が同じに動くこと
  • R2 の手元の機能: Worker のバインディングからの書き込み・消去を道具のサービスが見られるか(イベント通知とロックのため)。Wrangler の手元の模擬に公開・CORS・ライフサイクル・通知・ロック・保管の種類が本当に無いか(あればそれを使う)
