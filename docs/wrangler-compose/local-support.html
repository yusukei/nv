手元で使えないもの

wrangler-compose --env local up(中身は Wrangler の手元の開発。miniflare と workerd)で開発するときに、使えない・本番と振る舞いが違う Cloudflare の機能の一覧。要求仕様の REQ-018 の元になる。主に使う型(Workers・D1・R2・KV・Queues・Durable Objects・シークレット)のものが対象で、ほかの製品の行は参考として残す。Wrangler の版が上がれば変わるので、確かめた版と日付を書く: Wrangler 4.149.0、2026-10-11。

根拠の見方

根拠意味
実装Wrangler 4.149.0 の wrangler-dist/cli.js の決まり(バインディングは BINDING_LOCAL_SUPPORT の表)
資料Cloudflare の資料(cloudflare/cloudflare-docs の 2026-10-11 の版)。「Supported bindings per development mode」と各製品の Local development の頁
実測手元の Wrangler 4.149.0 で動かして確かめた
推測確かめていない。仕組みから見込んだもの。受け入れの前に確かめる

バインディング

Wrangler はバインディングの種類ごとに、手元で動くか・remote: true で Cloudflare の本物につなげるかを決めている。wrangler-compose はこの表に合わせて知らせる(REQ-021)。種類の名前は Wrangler の内側の名前。

手元では動かない(remote: true で本物につなぐ)

種類手元で起きること根拠
Vectorize(vectorize)remote を書かなければ、Wrangler が警告し、その部分が動かない。remote: false なら Wrangler が止まる実装・資料
mTLS 証明書(mtls_certificate)同上実装・資料
ディスパッチ名前空間(dispatch_namespace。Workers for Platforms)同上実装

手元でも常に Cloudflare につながる(料金がかかる)

Wrangler が「手元の代わりを作る予定は無い」としているもの。手元で動かしても Cloudflare の本物を使い、料金がかかり、本物のデータに触れる。

種類手元で起きること根拠
Workers AI(ai)常に Cloudflare で動く。remote: false なら Wrangler が止まる実装・資料
AI Search(ai_search・ai_search_namespace)同上実装
Media Transformations(media)同上実装・資料
VPC(vpc_service・vpc_network)同上実装
Artifacts・Agent Memory・Analytics・K2(artifacts・agent_memory・analytics・k2)同上実装

手元だけで動く(remote: true にできない)

種類手元で起きること根拠
Durable Objects手元で動き、データは手元の置き場。本物の Durable Objects を使いたければ、それを持つ Worker をデプロイし、手元からサービスバインディング(remote: true)で呼ぶ実装・資料
Workflows手元の模擬の Workflows で動く(Cloudflare のものと同じ実装ではない)実装・資料
Hyperdrive手元では Hyperdrive を通らず、データベースへ直につなぐ(接続の使い回しと問い合わせのキャッシュは効かない)。追加の用意が要る実装・資料
Analytics Engine書いたデータは本番の Analytics Engine に入らず、SQL API で読めない実装・資料
Rate Limiting手元の模擬。本番の上限とは数えが別実装・資料
Secrets Store手元の値を使う(本番の Secrets Store は読まない)実装
静的なファイル(assets)手元のディスクから配る実装・資料
Version Metadataデプロイした版の ID・タグは手元には無い(本物の値にならない)実装・資料
変数(vars)・シークレット.env.local・.dev.vars・設定の vars の値。Cloudflare に入れたシークレットは手元に来ない実装・資料・実測
Worker Loader・ログ転送(logfwdr)手元だけ実装

手元でも本物でも使える

種類手元で起きること根拠
D1・KV・R2既定は手元の模擬(.wrangler/compose/local/state/)。remote: true で本物につなぐ。R2 の S3 互換 API は wrangler-compose が手元で開く(REQ-009)実装・資料・実測
Queues手元の模擬。remote: true を書いても手元の模擬のまま(miniflare が無視する。workers-sdk #13727)実装
サービスバインディング同じ up で動かしたサービス(REQ-009)か、手元の別の dev につながる。remote: true でデプロイ済みの Worker につなぐ実装・資料・実測
Browser Run・Images・Stream・メールの送信(send_email)・Pipelines・Flagship既定は手元の模擬。メールは実際には送られず、内容が画面と手元のファイルに出る実装・資料

手元で動かすのに追加の用意が要るもの

機能要るもの・手元での使い方根拠
Hyperdrive手元の接続文字列。設定の localConnectionString か、環境変数 CLOUDFLARE_HYPERDRIVE_LOCAL_CONNECTION_STRING_<バインディング名>(手元のデータベースでも、Cloudflare の外のデータベースでもよい)資料
Containers手元で Docker が動いていること。FUSE は Docker が VM の中で動くとき(macOS・WSL など)に使える。Linux の rootful な Docker では既定で使えない資料
Cron Triggers手元では時刻が来ても動かない。curl "http://127.0.0.1:<ポート>/cdn-cgi/local/scheduled?cron=*+*+*+*+*" で呼ぶ資料
メールの受信(Email Routing)届いたメールの代わりに、POST http://127.0.0.1:<ポート>/cdn-cgi/local/email へメールの中身を送る資料

設定にあっても手元では効かないもの

設定手元で起きること・代わり根拠
ルート・カスタムドメイン(routes)・workers_dev・プレビューの URL手元の URL(http://127.0.0.1:<ポート>)だけで応える。ホスト名で振り分ける作りは、要求の Host を手で付けて試す推測
Cron(triggers.crons)自動では動かない(上)資料
Smart Placement(placement)手元では意味が無い(Worker は手元で動く)推測
CPU 時間などの上限(limits)手元で本番と同じに打ち切られるかは確かめていない推測
ログ(observability・Logpush・tail_consumers)手元のログ(console と要求ごとの記録)は画面に出る。Tail Worker は同じ up で動かせば手元でつながる。Workers Logs・Logpush には送られない資料・実測
remote: true のバインディング手元の開発でも Cloudflare の本物の資源につながる。local は設定の一番上の階層を使うので、一番上に本番の ID を書いていれば本番のデータに触れる資料

設定に出ないが本番と違うもの

機能手元で起きること根拠
request.cf(国・都市・ASN など)Cloudflare から取れればその値(使う人の場所ではなく自分の回線のもの)、取れなければ決まった代わりの値実測(取れないときの警告)
ゾーンの機能(WAF・キャッシュのルール・リダイレクト・Access・Bot 対策など)要求が Cloudflare の網を通らないので、どれも効かない。Access の JWT のような付け足されるヘッダも来ない推測
R2 の公開の URL(r2.dev・独自ドメイン)無い。Worker を通して配るか、手元の S3 の口の署名付き URL を使う(範囲外。workers-sdk #3687 で要望が出ている)資料(要望の issue)
R2 のバケットの設定(CORS・ライフサイクル・イベント通知)手元のバケットには当たらない見込み。ブラウザから署名付き URL を使うときの CORS の振る舞いは本番と違いうる推測
D1 の Time Travel・読み取りの複製手元の D1 には無い推測
KV の結果整合性手元では書いた値がすぐ読める。本番の「しばらく古い値が見える」は再現されない推測
キャッシュ(Cache API・fetch のキャッシュ)手元のキャッシュで、本番の拠点ごとのキャッシュとは振る舞いが違う推測

R2 の機能ごとの手元の状況

基準は「ふつうのプロダクトを作るのに無いと困る機能を、本物と同じに提供する。ほとんど使わない機能は再現しない」(REQ-009。利用者の決定)。「無い」の判断は Wrangler の変更履歴と実測からの見立てで、作る前に一つずつ実物で確かめる。

R2 の機能Wrangler の手元の模擬手元での扱い(決定)
バインディングの API(get・put・head・list・delete・分割アップロード・条件つき・範囲指定・メタデータ)ある再現する(そのまま使う)
S3 互換の API・署名付き URLある(4.115.0 から。実測)再現する(そのまま使う)
CORS無い再現する(道具のサービス)。ブラウザから署名付き URL で直接上げるときに要る
公開の URL(r2.dev・独自ドメイン)無い再現する(道具のサービス)
イベント通知(オブジェクトの変化を Queue へ)無い再現する(道具のサービス)
ライフサイクル(期限で消す・保管の種類を変える)無い再現しない。手元の開発で期限切れを待つことはまず無い。リモートには設定を入れる
オブジェクトのロック・保管の種類無い再現しない。ほとんど使わない。リモートには設定を入れる

足りないものwrangler-compose での扱い
R2 の S3 互換 API・署名付き URL--env local up が手元の S3 の口を開く(REQ-009)
