wrangler-compose 要求仕様

03. 全体の条件と範囲

どの操作にも掛かる決まり(安全・手で行う段取り・道具のサービス・違いの知らせ・配り方)と、範囲外。REQ-015〜019。

要求

REQ-015安全

  • リモートに展開するのは、手元と同じ組み立てたものだけ(REQ-010)
  • 消す操作は、消すものを示し、環境名の打ち直しで確かめる
  • まだ無い環境への初めての up は、新しく作ることを示して確かめる(環境名の打ち間違いで新しい環境を建てない)
  • リモートの up は、上の初めての環境と消す操作のほかは、確かめを求めずに進める(CI から展開できるように。利用者の決定 2026-10-13)
  • シークレットの値を、どの操作でも画面・ログ・バックアップに出さない
  • .env.<環境> とバックアップが git に入る形なら止まる

REQ-016手で行う段取りを持たない

  • 利用者が用意するのは、compose ファイル・コード・.env.<環境> だけ。人が行うのは Cloudflare へのログインを 1 度だけ
  • 資源の作成、移行、シークレットの投入、手元の S3 互換の API の鍵など、ほかに要るものはすべて道具が用意する。ただし、リモートの R2 の S3 互換の API の鍵はアプリの側で扱う(REQ-004。利用者の決定 2026-10-13)

REQ-017道具のサービス

  • 道具のサービスは手元(--env local)だけに置く。リモートの環境には置かない

REQ-018手元と本番の違いの知らせ

  • 手元で動かしたときに本番と振る舞いが違う点を、手元で使えないものに、使う型に絞って列挙する
  • --env local up は、compose ファイルにそれに当たるもの(routes・crons など)があれば、動かす前に、手元ではどうなるか・どう試すかを示す

REQ-019配り方・表示の言語

  • OS ごとの単体の実行ファイルで、nv と同じ Release で配る。nv と同じフォルダに置いて使う
  • メッセージと --help は、nv と同じ決め方で日本語か英語で出す。打ち直しの確かめで打つのは環境名そのもの

範囲外

  • 使わない型(Vectorize・Workers AI・Hyperdrive・Workflows など)。使うときに型を足す
  • docker compose にあって要らないもの: image(type が代わり)・-f(--env が代わり)・profiles・extends・include・networks・volumes・scale・exec・run
  • DNS・WAF・Access などゾーンの設定
  • Wrangler のコマンドでも Cloudflare の API でも行えない操作
