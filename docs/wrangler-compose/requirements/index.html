wrangler-compose 要求仕様

全体像

docker compose のように手元で開発し、それを安全に Cloudflare(リモート)へ展開する道具。要求仕様は「何ができるべきか」だけを書く。どう作るか(どの道具を中で使うか)は詳細仕様で決める。

何のためのものか

手元(local)で開発したサービスを、安全にリモート(Cloudflare の環境)へ展開する。

これが定義の 1 つ目で、すべての要求はここから決める。定義の全文・理念・利用者の決定・用語は決定と用語にある。

手元で動いたものと同じ組み立てたものを、staging、production の順に展開する。環境の違いは .env.<環境> の値だけで表し、compose ファイルは 1 つ(REQ-004)。

compose ファイルとつながり

docker compose の image の代わりに type を置き、Worker も D1・R2・KV・Queue もサービスとして並べる。1 つのサービスは 1 つの Worker か 1 つの資源。下はcompose ファイルの例のつながりを図にしたもの。

Worker(作り直せるもの)資源(中身はデータ) ／ 線の名前は Worker から見える名前(env.<名前>)

つながる相手は先に建てる。つながりは手元でもリモートでも同じに働く(REQ-003)。

名前と持ち主

リモートの Worker と資源の名前は、道具が <プロジェクト>--<環境>--<名前> で決める。名前から、どのプロジェクトのどの環境のものかが必ず分かり、道具が作る・使う・消すのはその環境のものだけ(REQ-006)。

手元(--env local)でも、プロジェクトごとにプロセス・待ち受けのポート・データの置き場・Worker の呼び出し先の登録を分け、ほかのプロジェクトと共有しない(定義 3・REQ-009)。手元のものがリモートの資源に触れることも、その逆も無い。

作り直せるものとデータ

Worker は compose ファイルとコードから up で同じものができる。D1・R2・KV・Queue と Durable Objects の中身はデータで、作り直せない。データは明示したときだけ消す。

操作Workerデータ(D1・R2・KV・Queue)確かめ要求
up展開する。リモートでは compose ファイルに無い、この環境の Worker を消す無ければ作り、移行を当てる。compose ファイルに無いものは示すだけで消さないまだ無い環境への初めての up。Durable Object を消すときは、消す・残す・やめるを選ばせるREQ-010・015
up --purgeup と同じcompose ファイルに無い、この環境のものも消す環境名を打ち直すREQ-010
down依存の逆の順に下ろす残すリモートは環境名を打ち直す。手元は確かめないREQ-011
down --purge下ろす消す環境名を打ち直す(手元も)REQ-011・015

消す操作は、消すものを示してから環境名の打ち直しで確かめる。打ち直しを受けられない場(CI など)では止まる。

受け入れ条件

要求仕様の REQ-001〜019 を満たしたと言える条件。番号は要求と 1 対 1。手元(--env local)の条件は網を切った PC でも確かめられ、CI(Windows・macOS・Linux)で毎回動かす。リモートの条件は、試験用の Cloudflare アカウントの使い捨ての環境(--env ac-1 など)で、利用者の許可を得てから確かめる。本番では行わない。
