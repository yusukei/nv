02. コマンド

build・up・down・ps・logs・backup・restore・--dry-run が何をするか。REQ-008〜014。

使い方の流れ

wrangler-compose --env local up              # 手元で開発する(全サービスが手元で動く)
wrangler-compose --env staging --dry-run up  # staging に何が起きるかを見る

wrangler-compose --env production --dry-run up
wrangler-compose --env production up         # 同じものを本番へ展開する

要求

REQ-008build

  • build [サービス…] は、docker compose の build と同じく、Worker を組み立てるだけで、何も建てない・動かさない
  • 組み立てたものは環境によらず同じ。環境ごとの値は組み立てたものに入れず、up が環境に合わせて渡す
  • 組み立てられなければ、どのサービスがなぜかを示して止まる

REQ-009up(手元)

  • --env local up は、Cloudflare に触れず(ログインも網も要らず)、すべてのサービスを手元で動かす。前面で動き、Ctrl+C ですべてのプロセスが止まる(データ・組み立てたもの・手元の S3 の鍵は残る)
  • 手元では、ふつうのプロダクトを作るのに無いと困る機能を、本物と同じに提供し、同じに振る舞わせる(動作が違えば手元で開発する意義が薄れるため。利用者の決定)。本物にあって手元の模擬に無いものは、道具のサービス(REQ-017)で補う
  • 実際のプロダクトでほとんど使わない機能は、手元で再現しない(利用者の決定)。再現しないものは 手元で使えないものに理由とともに書く
  • r2 のサービスに ports を書くと、そのポートが手元の R2 の口になる: S3 互換の API(署名付き URL を含む)は http://127.0.0.1:<ポート>/cdn-cgi/local/r2/s3 で、CORS はバケットの cors どおりに答える。public: true のバケットは http://<バケット名>.localhost:<ポート>/<キー> で配る(利用者の決定)。public_port を書いたバケットは、そのポートでも http://<PC のアドレス>:<public_port>/<キー> で配る。待ち受けるアドレスは r2 のサービスの ports と同じで、0.0.0.0 なら HMD・スマートフォンなど LAN の機械から届く(手元だけ。リモートでは使わない)(利用者の決定 2026-10-13「LAN で使えないと困ります」)。ports が無いと CORS と公開の URL は本番と同じにならず、up がそのことを知らせる
  • ports にアドレスを書いて外(LAN)にも開いた口(0.0.0.0:9050:9050 など)は、ほかの機械(HMD・スマートフォン・別の PC)から、その機械のアドレスで届いた要求にも同じに応える。そのアドレスで作った署名付き URL は通り、署名が合わなければ本物と同じに拒む(利用者の決定 2026-10-12「LAN経由で動作しなければ意味がないです」)。ほかの機械が届くのは IP アドレスで、名前(DNS の名前)で届いた要求は手元の模擬と同じに拒む(悪いページが自分の名前を 127.0.0.1 に向け直して手元の口を読むのを防ぐ。利用者の決定 2026-10-12)
  • R2 は、手元でも本物と同じに使える: バインディングの API、S3 互換の API(署名付き URL を含む)、CORS、公開の URL、イベント通知(Queue へ)。ライフサイクル・オブジェクトのロック・保管の種類は手元では再現しない(リモートには設定を入れる)(利用者の決定)
  • D1・KV・Queue は、ふだん使う API(読み書き・一覧・一括処理・移行・送受信・やり直しなど)を手元でも本物と同じに使える。Queue の受け手は、手元でも本物の既定値(1 回にまとめる数 10・待つ時間 5 秒・やり直し 3 回)で動く。D1 の上限の一部・KV の結果整合・Queue の同時処理などは手元で再現しない(手元で使えないものに理由とともに書く)(利用者の決定)
  • それでも本物と違うところは、手元で使えないものに理由とともに書き、無くしていく(REQ-018)
  • 同じ資源を使うサービスが同時に書いても、データが失われない
  • ports を書いた Worker は、それぞれその手元の URL で応える
  • コード・compose ファイル・.env.local が変われば組み立て直して動かし直す(読めない compose ファイルのあいだは今のまま動かす)。移行は動かす前に当てる
  • 手元のデータは down では残り、down --purge で消える
  • 同じプロジェクトで 2 つ目の --env local up は止まる。ただし down <サービス> で外したサービスがあれば、それを動いている up に戻す(REQ-011)。ほかの端末からの --env local down で止められる
  • 別のプロジェクトの --env local up とは、同時に動かせる(定義 3)。ports のポートをほかのもの(別のプロジェクト・ほかのプログラム)が使っているときは、その通信を横取りせず、何も動かさずに止まり、どのポートかを示す

リモートの up の順

利用者wrangler-composeCloudflare(この環境)止まる ／ 点線の箱は --purge のときだけ

REQ-010up(リモート)

  • リモートの up は、手元と同じ組み立てたもの(REQ-008)を展開する。組み立てたものが無いか、コードが変わっていれば組み立て、--build なら必ず組み立て直す
  • 依存の順に: 資源が無ければ作る → 移行を当てる → Worker をシークレットとともに展開する(compose ファイルから消えたシークレットは展開のあとで消す)
  • 何度打っても同じ結果になる。変わっていないものは変えない
  • 移行が失敗したら、その D1 を使う Worker は展開しない。どこまで済み、どこでなぜ止まったかを示し、それより後は行わない
  • 名前がこの環境のもの(<プロジェクト>--<環境>-- で始まる)で、compose ファイルに無い Worker は、up が消す(Cloudflare には切り離しが無く、残った Worker は公開の URL で動き続けるため。利用者の決定 2026-10-13)。どの PC から打っても同じものを消す。Durable Object を持つ Worker は、消すと保存データも消えるので、Durable Object のクラスと同じく、消す・残す・やめるを選ばせる(端末で選べない場では止まる)
  • up --purge は、さらに、名前がこの環境のもので compose ファイルに無い D1・KV・R2・Queue も消す。データが消えるので、消すものを示して環境名の打ち直しで確かめる(端末で打ち直せない場では止まる)。--purge の無い up は、それらを示すだけで消さない(利用者の決定 2026-10-13)
  • compose ファイルから消えた Durable Object のクラスは、up がその場で、消す・残す・やめるのどれかを選ばせる。消すと保存データも消える(消すときは環境名を打つ)。残すときは、コードからもクラスを消さない。やめると何も変えずに止まる。端末で選べない場(CI)では止まる。保存データの形の移行はアプリの側で扱う(利用者の決定 2026-10-13)
  • 移行を当てるときに確認を求めない

REQ-011down

  • down [サービス…] は Worker を依存の逆の順に下ろし、データは残す。そのあとの up で元に戻る
  • down --purge [サービス…] はデータも消す。下ろさないサービスがつながる資源は消さずに止まる
  • リモートの down --purge は、下ろすサービスのコンテナのイメージ(道具が名前を決めたもの)を Cloudflare のレジストリからも消す。前の down で Worker がもう無くても、compose ファイルのコンテナのものは消す。利用者が自分で置いたイメージ(image にレジストリのイメージとして書いたもの)と、展開した PC の Docker に残るイメージは消さない(利用者の決定 2026-10-13)
  • サービスを指定しない down --purge は、名前がこの環境のもの(<プロジェクト>--<環境>-- で始まる)の Worker と資源をすべて消す。compose ファイルから消したものも含み、環境に何も残らない(利用者の決定 2026-10-13)
  • 消す前に消すもの(Worker・資源の名前。手元は中身の数も。リモートは中身の数を出さない(利用者の決定 2026-10-13))を示し、環境名を打ち直して確かめる(手元の --purge も)。打ち直しを受けられない場では止まる。リモートの down は Worker を消すので、--purge が無くても確かめる。手元の down(データを消さない)は確かめない

REQ-012ps・logs

  • ps は、サービスごとの状態(あるか・動いているか・URL・未適用の移行)と、compose ファイルとの違い(足りないもの・残っているもの)を示す。何も変えない
  • logs [-f] [サービス…] は、Worker のログを docker compose と同じく行の頭にサービス名を付けて出す。リモートは Cloudflare から過去のログが取れないので、-f の有無によらず今からのログを追う(Ctrl+C で止まる)(利用者の決定 2026-10-13)

restore --drop の流れ

利用者wrangler-compose戻す先の環境失敗したとき

--drop が無いときは、戻す先が空のときだけ戻す。

REQ-013backup・restore

  • backup は、その環境の D1・R2・KV の中身を手元のフォルダ(既定は backups/<環境>/<日時>/)へ書き出す
  • restore <バックアップ> は、サービスの名前で照らしてその環境へ戻す。戻す先が空のときだけ戻し、--drop ならいまの中身を消してから戻す(打ち直しで確かめる)。消す前にいまの中身をバックアップし、その場所を示す。戻すのに失敗したらバックアップした中身に戻し、それも失敗したら、バックアップした場所と戻し方(restore --drop <その場所>)を示して止まる(利用者の決定 2026-10-13)。戻したあと、バックアップのあとの移行を当てる
  • バックアップはどの環境のものでも、どの環境へでも戻せる。データはバックアップのファイルを間に置いて移す(移し元の中で書き出し、移し先の中で読み込む)
  • リモートの環境の中身は Wrangler のコマンドか Cloudflare の API で書き出し・読み込む
  • バックアップは git に入れない。書きかけのバックアップと、壊れた・書き換えられたバックアップ(ファイルごとの SHA-256 が合わないもの)は戻さない(利用者の決定 2026-10-13)。Durable Objects・Queue の中身とシークレットはバックアップしない

REQ-014dry-run

  • --dry-run はどの操作にも付き、何も変えずに何が変わるか(作る・変える・消すもの、当てる移行、入れる・消すシークレットの名前、展開した値)を示す。シークレットの値は出さない
  • リモートの up の --dry-run は、terraform plan のように、作る・変える・消す・変わらないものを、変わる項目の前後の値とともに示す。比べる相手は Cloudflare にいまあるもので、どの PC から打っても同じ結果になる。シークレットは名前だけを示す(値が変わったかは示さない)(利用者の決定 2026-10-13)
  • 本番の操作がエラーで止まる条件では、dry-run も同じエラーで止まる
