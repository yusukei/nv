nv 設計

nv の要求仕様(REQ)と受け入れ条件(AC)を満たす作り。各 DES に、採る方式・却下した方式・成り立たない場合を書く。

確かめた事実

事実出典
Node の配布物は node-v<版>-<OS>-<CPU>.tar.gz(darwin・linux。.tar.xz もある)と node-v<版>-win-x64.zip(.7z もある)。検証値は同じフォルダの SHASUMS256.txtnodejs.org/dist/v24.11.1/SHASUMS256.txt
npm のロックファイル(lockfileVersion 3)の packages の各項目に、そのパッケージが入れる道具の名前と入口(bin)が載る。例: wrangler 4.128.0 は {"wrangler":"bin/wrangler.js", …}marche-ar の workers/delivery/package-lock.json で実測
Rust の Command は Windows で、子に渡した PATH を最初に探す。.exe 以外は拡張子を付けないと見つからないstd::process::Command
Rust 1.77.2 以降、.bat・.cmd へ渡す引数を安全に包めないとき、Command は起動時に InvalidInput で失敗する(正しい引数を拒むこともある)CVE-2024-24576(Tenable・Debian)
std::fs::File::lock(排他、取れるまで待つ)は Rust 1.89.0 で安定。Unix は flock、Windows は LockFileExstd::fs::File::lock
ureq 3 の Proxy::try_from_env() は ALL_PROXY・HTTPS_PROXY・HTTP_PROXY を読み、NO_PROXY も効く。既定の設定がこれを使う(ureq 3.4.2 の src/config.rs の既定値 proxy: Proxy::try_from_env())ureq::Proxy・ソース
Codex が利用者全体のスキルを読む場所は $HOME/.agents/skillsOpenAI「Build skills」

設計

DES-001作りの全体 REQ-009

  • Rust の 1 つのワークスペースに、実行ファイルごとのクレート crates/nv と crates/wrangler-compose を置く。2 つは互いのコードに頼らない(要求の境目のとおり)。nv が wrangler-compose について知るのは、実行ファイルの名前とスキルの中身だけ
  • Rust の最低の版は 1.89(File::lock を使うため)
  • 頼るクレート: clap(引数)、ureq 3(HTTP。TLS は rustls)、sha2、flate2+tar(.tar.gz)、zip(Windows)、serde_json(ロックファイル)
  • 却下: reqwest(非同期の実行環境を抱え、実行ファイルが大きくなる。nv の取得は 1 本ずつで足りる)
  • 却下: .tar.xz を取る(小さいが、xz の展開に C のライブラリか重いクレートが要る。.tar.gz は純 Rust で展開できる)

DES-002~/.nv の中身 REQ-002・REQ-003・REQ-005・REQ-007

場所中身
~/.nv/cache/node/<版>/展開した Node(macOS・Linux は bin/node、Windows は node.exe)。npm は Node に付いてくるものを使う
~/.nv/cache/npm/nv が動かす npm のキャッシュ
~/.nv/cache/tools/<パッケージ>@<版>/node-<Node の版>/nv x で入れた道具(スコープの / は + に置き換える)
~/.nv/cache/tmp/取得と展開の途中のもの。置き場と同じディスクに置き、済んだら名前の付け替えで移す
~/.nv/cache/locks/取り合いを防ぐ錠のファイル
  • ホームは、Windows は USERPROFILE、ほかは HOME から得る
  • 環境変数 NV_HOME があれば ~/.nv の代わりに使う(試験で、利用者の ~/.nv を汚さずに回すため。利用者向けには書かない)
  • 却下: OS の作法に従って分ける(uv の形)。利用者の決定で ~/.nv にまとめる

DES-003プロジェクトと Node の版の見つけ方 REQ-001・REQ-005

  • いまいるフォルダから上へたどり、最初に package.json があるフォルダをプロジェクトとする
  • .node-version と package-lock.json は、そのプロジェクトのフォルダにあるものだけを読む(上へは探さない。「1 か所で決める」ため)
  • .node-version は前後の空白と行末を除いた 1 行。先頭の v は受ける(fnm などが書く形)。それ以外は 数.数.数 だけを受ける
  • 成り立たない場合: npm のワークスペースの子のフォルダで打つと、子の package.json がプロジェクトになり、ロックファイルが無くて止まる。ワークスペースは範囲外として、止まったときに上のフォルダで打つよう示す

DES-004Node の取得 REQ-002

  1. 錠 locks/node-<版>.lock を取る(File::lock。取れるまで待つ)。取ったあと、置き場にその版があれば何もしない(先に取った nv が入れたもの)
  2. 取り先(既定 https://nodejs.org/dist。環境変数 NV_NODE_MIRROR で差し替え)から v<版>/SHASUMS256.txt と配布物を tmp/ へ取る
  3. 配布物の SHA-256 を SHASUMS256.txt の行と照らす。合わない・行が無いときは消して止まる
  4. tmp/ の中で展開し、配布物の一番上のフォルダ(node-v<版>-<OS>-<CPU>)を cache/node/<版> へ名前の付け替えで移す。移すのが最後の一手なので、途中で止まっても半端な版は置き場に無い
  5. 起動のたびに、tmp/ に残った古いもの(1 日より前)を消す
  • HTTP はすべて ureq の既定の設定の 1 つの Agent で行う(環境変数のプロキシを読む)
  • 却下: 置き場に「済み」の印のファイルを書いて見分ける(印と中身がずれうる。名前の付け替えなら、ある=完成している)
  • 成り立たない場合: 取り先を差し替えると、SHASUMS256.txt も同じ取り先から来るので、壊れていないことは分かるが本物であることは保証しない(公式の署名 SHASUMS256.txt.asc は確かめない。要求の範囲)

DES-005sync と「依存が揃っているか」 REQ-003・REQ-004

  • 依存を入れるのは npm ci。npm は Node に付いてくる npm-cli.js を node で直接動かす(Windows で npm.cmd を通さない)
  • npm には環境変数 npm_config_cache=~/.nv/cache/npm を渡す
  • 入れ終えたら node_modules/.nv-sync に、package-lock.json の SHA-256 と Node の版を書く。次の nv run は、この 2 つがいまと同じなら入れ直さない。違えば(ロックファイルを変えた・Node の版を変えた)入れ直す
  • 入れ直すときは、プロジェクトのフォルダごとの錠を取る(同じプロジェクトで 2 つの nv が同時に npm ci を走らせて node_modules を壊さない)。錠を取ったあと印を見直し、先の nv が入れ終えていれば入れ直さない
  • 却下: npm が書く node_modules/.package-lock.json と比べる(npm の内部の形で、版によって変わりうる)
  • 却下: ファイルの更新時刻で比べる(git の取り直しで時刻が変わり、当てにならない)
  • 成り立たない場合: 利用者が nv を通さずに node_modules の中を書き換えると、印は合ったままなので気付かない。nv sync を打てば、印に関係なく入れ直す

DES-006run REQ-004

コマンドの名前から、動かすものを次の順に決める。

  1. node → 揃えた Node の実行ファイル
  2. npm・npx → node で Node に付いた npm-cli.js・npx-cli.js
  3. プロジェクトの依存の道具 → package-lock.json の packages の bin から、その名前の入口のファイルを引く。入口が JavaScript(拡張子が .js・.mjs・.cjs、または先頭行が node を指す #!)なら node <入口> 引数… で動かす。そうでなければ(esbuild のような実行ファイル)そのまま動かす
  4. どれでもなければ、子の PATH から探す(Windows で .cmd しか無ければ、その .cmd を拡張子付きで起動し、引数は Rust の標準の包み方に任せる)
  • package-lock.json がまだ無いプロジェクトでは、依存を揃えずに Node だけを揃えて動かす(最初の nv run npm install でロックファイルを作れるようにする)
  • nv run・nv x の後ろの引数はすべて動かすコマンドのもので、--help・--version も nv は受け取らない
  • 子の環境: PATH の先頭に、Node のフォルダ → プロジェクトの node_modules/.bin の順で足す(子がさらに起こす node・npm も揃えたものになる)。npm_config_cache も渡す
  • シェルは通さない。macOS・Linux では exec で nv 自身を置き換える(終了コードとシグナルがそのまま利用者に届く)。Windows では起こして待ち、終了コードを返す(Ctrl+C は子にも届くので、nv はそれで終わらず子の終わりを待つ)
  • 却下: 常に node_modules/.bin の .cmd を起動する(Windows で引数が cmd.exe の解釈を通り、& などが壊れる・拒まれる。入口を引けば cmd.exe を通らない)
  • 成り立たない場合: ロックファイルに bin の無い古い形(lockfileVersion 1)では入口を引けず、4 の .cmd に落ちる。Windows でそのとき、% などを含む引数は拒まれることがある(拒まれたら、その旨を示して止まる)

DES-007x REQ-005

  • 入れる先は cache/tools/<パッケージ>@<版>/node-<Node の版>/(Node の版ごとに分ける。ネイティブの部品が Node の版に縛られるため)
  • 無ければ、錠を取り、tmp/ の中に空の package.json を作って npm install <パッケージ>@<版> を動かし、済んだら名前の付け替えで移す(DES-004 と同じ形)
  • 動かす道具は、入れたパッケージの package.json の bin から選ぶ。1 つならそれ、複数ならパッケージ名(スコープを除く)と同じ名前のもの。どちらでもなければ、選べる名前を示して止まる
  • 動かし方は DES-006 の 3 と同じ

DES-008node list / install / uninstall REQ-006

  • list は cache/node/ のフォルダ名を版の順に並べる。install は DES-004。uninstall は錠を取ってフォルダを消す

DES-009エージェント用のスキル REQ-008

  • スキルの中身(SKILL.md)は、nv の実行ファイルに埋め込む(include_str!)。nv の版とスキルの中身が必ず一致する
  • スキルは 2 つ: nv と wrangler-compose。入れる先は ~/.agents/skills/<名前>/(常に)と ~/.claude/skills/<名前>/(~/.claude があるときだけ)
  • nv が入れたことの印として、各フォルダに .nv-managed(入れた nv の版)を置く。uninstall skill は印のあるフォルダだけを消す。入れる先に印の無い同じ名前のフォルダがあれば、上書きせずにそのことを示す(利用者が自分で置いたものを壊さない)
  • 入れるときは、tmp/ に作ってから付け替える(2 回打っても 1 つ)
  • 成り立たない場合: Codex が置き場を変えたら、入れても効かない。置き場は 1 か所の定数にして、変わったら nv の版を上げて直す

DES-010配り方 REQ-009

  • Release に置くもの: 実行ファイルそのもの(包まない)を、nv-<ターゲット>[.exe]・wrangler-compose-<ターゲット>[.exe] の名前で。検証値の一覧 SHA256SUMS。版の文字列だけを書いた VERSION
  • ターゲット: x86_64-pc-windows-msvc・aarch64-apple-darwin・x86_64-apple-darwin・x86_64-unknown-linux-musl(静的にリンクし、どの Linux でも動く)
  • GitHub Actions: v* のタグの push で、Windows・macOS・Ubuntu の機械で組み、最後の 1 つの仕事が SHA256SUMS と VERSION を作って Release に上げる。タグの版と Cargo.toml の版が違えば失敗させる
  • 最初の導入は README に、OS ごとの取り方(macOS・Linux は curl、Windows は PowerShell の Invoke-WebRequest)を書く
  • 却下: .tar.gz・.zip に包む(展開の手間が増えるだけで、単体の実行ファイルには得が無い)
  • 成り立たない場合: macOS でブラウザから取ると、隔離の印が付き、署名の無い実行ファイルは止められる。README の取り方は curl にする(印が付かない)。署名と公証は範囲外

DES-011self update REQ-010

  1. 取り先(既定 https://github.com/<持ち主>/<リポジトリ>/releases/latest/download。環境変数 NV_RELEASE_MIRROR で差し替え)から VERSION を取り、いまの版と比べる。新しくなければ「最新」と示して終わる。--check はここで終わる
  2. SHA256SUMS と、自分のターゲットの nv-…(同じフォルダに wrangler-compose があればそれも)を、入れ替える実行ファイルと同じフォルダの一時ファイルへ取り、照らす。1 つでも合わなければ全部消して止まる
  3. 入れ替え: いまのファイルを <名前>.old へ名前を付け替え、取ったものを本来の名前へ付け替える(Windows でも、動いている実行ファイルの名前の付け替えはできる)。2 つ目の付け替えに失敗したら、.old を戻す
  4. 新しい nv を nv install skill --if-installed(内部の引数)で起こし、印のあるスキルだけを新しい中身で入れ直す(古い nv は新しいスキルの中身を持たないため)
  5. nv は起動のたびに、自分のフォルダの .old を消す(Windows では入れ替えたときに消せないため)
  • 却下: GitHub の API(/repos/…/releases/latest)で版を調べる(認証の無い呼び出しの回数制限があり、プロキシの網で別の口が要る。latest/download なら資産と同じ口で済む)
  • 成り立たない場合: 実行ファイルのフォルダに書けない(管理者の場所に置いた)と入れ替えられない。そのときは書けないことと場所を示して止まる

DES-012出力と終了コード REQ-004・REQ-007

  • nv 自身の出力は標準エラーに出す。標準出力は動かしたコマンドのものだけにする
  • 言語(REQ-011)は起動のはじめに 1 度だけ決める: NV_LANG → LC_ALL・LC_MESSAGES・LANG(Unix)→ macOS は defaults read -g AppleLanguages の先頭 → Windows は GetUserDefaultUILanguage の主言語。ja で始まれば日本語、決まらなければ英語
  • メッセージは、出す箇所に日本語と英語を並べて書く(tr!("日本語", "English"))。訳の表を別のファイルに持たない(訳し漏れと、鍵と文のずれを起こさない)
  • --help の説明は、組んだコマンドの定義に日本語の説明を当て直してから引数を読む。clap 自身の出すエラーの文(未知の引数など)は英語のまま
  • Windows の端末へは、Rust の標準の出力が UTF-8 を端末の文字に変えて書くので日本語は化けない(Rust の資料: 端末への出力は UTF-8 だけを受ける)。ファイルやパイプへは UTF-8 のまま書く
  • 却下: 英語だけ(日本語の環境の利用者に読みにくい。利用者の決定)。却下: 日本語だけ(公開のリポジトリで、日本語を読めない人が使えない)
  • nv 自身が止まったときの終了コードは 2。動かしたコマンドの終了コードはそのまま返す

DES-013試験

  • 単体の試験: 版の読み取り、SHASUMS256.txt の照合、ロックファイルの bin の引き方、入口が JavaScript かの見分け
  • 結合の試験(NV_HOME を一時のフォルダにして実行ファイルを動かす): 手元で配る偽の取り先(検証値の合わない配布物、途中で切れる応答)で AC-002・AC-010 の失敗の側を確かめる。本物の取り先での取得は CI の 1 つの仕事で行う
  • CI は Windows・macOS・Linux の 3 つで回す。エージェントの振る舞い(AC-008 の 3 回)は手で確かめる

確かめていないこと(作る前に確かめる)

  • Windows で、動いている実行ファイルの名前の付け替えが、権限の無い利用者でもできるか(一般に知られた動きだが、実機で確かめる)
  • npm の npm_config_cache が、npm ci・npm install の両方でキャッシュの場所を変えるか
  • macOS の隔離の印が、curl で取ったファイルに付かないこと
  • GitHub の releases/latest/download/<資産> が、リポジトリの持ち主と名前が決まった後の公開リポジトリで期待どおり転送されること(リポジトリの名前が決まるまで、取り先は仮)
