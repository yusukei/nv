nv 詳細仕様

D02. Node の取得と実行

Node を取り、依存を揃え、コマンドを動かす。DES-004〜008・DES-014。

設計

DES-004Node の取得 REQ-002

  1. 錠 locks/node-<版>.lock を取る(File::lock。取れるまで待つ)。取ったあと、置き場にその版があれば何もしない(先に取った nv が入れたもの)
  2. 取り先 https://nodejs.org/dist から v<版>/SHASUMS256.txt と配布物を tmp/ へ取る
  3. 配布物の SHA-256 を SHASUMS256.txt の行と照らす。合わない・行が無いときは消して止まる
  4. tmp/ の中で展開し、配布物の一番上のフォルダ(node-v<版>-<OS>-<CPU>)を cache/node/<版> へ名前の付け替えで移す。移すのが最後の一手なので、途中で止まっても半端な版は置き場に無い
  5. 起動のたびに、tmp/ に残った古いもの(1 日より前)を消す
  • HTTP はすべて ureq の既定の設定の 1 つの Agent で行う(環境変数のプロキシを読む)
  • 却下: 置き場に「済み」の印のファイルを書いて見分ける(印と中身がずれうる。名前の付け替えなら、ある=完成している)

DES-005sync と「依存が揃っているか」 REQ-003・REQ-004

  • 依存を入れるのは npm ci。npm は Node に付いてくる npm-cli.js を node で直接動かす(Windows で npm.cmd を通さない)
  • npm には環境変数 npm_config_cache=~/.nv/cache/npm を渡す
  • 入れ終えたら node_modules/.nv-sync に、package-lock.json の SHA-256 と Node の版を書く。次の nv run は、この 2 つがいまと同じなら入れ直さない。違えば(ロックファイルを変えた・Node の版を変えた)入れ直す
  • 入れ直すときは、プロジェクトのフォルダごとの錠を取る(同じプロジェクトで 2 つの nv が同時に npm ci を走らせて node_modules を壊さない)。錠を取ったあと印を見直し、先の nv が入れ終えていれば入れ直さない
  • 却下: npm が書く node_modules/.package-lock.json と比べる(npm の内部の形で、版によって変わりうる)
  • 却下: ファイルの更新時刻で比べる(git の取り直しで時刻が変わり、当てにならない)
  • 成り立たない場合: 利用者が nv を通さずに node_modules の中を書き換えると、印は合ったままなので気付かない。nv sync を打てば、印に関係なく入れ直す

DES-006run REQ-004

コマンドの名前から、動かすものを次の順に決める。

  1. node → 揃えた Node の実行ファイル
  2. npm・npx → node で Node に付いた npm-cli.js・npx-cli.js
  3. プロジェクトの依存の道具 → package-lock.json の packages の bin から、その名前の入口のファイルを引く。入口が JavaScript(拡張子が .js・.mjs・.cjs、または先頭行が node を指す #!)なら node <入口> 引数… で動かす。そうでなければ(esbuild のような実行ファイル)そのまま動かす
  4. どれでもなければ、子の PATH から探す(Windows で .cmd しか無ければ、その .cmd を拡張子付きで起動し、引数は Rust の標準の包み方に任せる)
  • package-lock.json がまだ無いプロジェクトでは、依存を揃えずに Node だけを揃えて動かす(最初の nv run npm install でロックファイルを作れるようにする)
  • nv run・nv x の後ろの引数はすべて動かすコマンドのもので、--help・--version も nv は受け取らない
  • 子の環境: PATH の先頭に、Node のフォルダ → プロジェクトの node_modules/.bin の順で足す(子がさらに起こす node・npm も揃えたものになる)。npm_config_cache も渡す
  • シェルは通さない。macOS・Linux では exec で nv 自身を置き換える(終了コードとシグナルがそのまま利用者に届く)。Windows では起こして待ち、終了コードを返す(Ctrl+C は子にも届くので、nv はそれで終わらず子の終わりを待つ)
  • 却下: 常に node_modules/.bin の .cmd を起動する(Windows で引数が cmd.exe の解釈を通り、& などが壊れる・拒まれる。入口を引けば cmd.exe を通らない)
  • 成り立たない場合: ロックファイルに bin の無い古い形(lockfileVersion 1)では入口を引けず、4 の .cmd に落ちる。Windows でそのとき、% などを含む引数は拒まれることがある(拒まれたら、その旨を示して止まる)

DES-007x REQ-005

  • 入れる先は cache/tools/<パッケージ>@<版>/node-<Node の版>/(Node の版ごとに分ける。ネイティブの部品が Node の版に縛られるため)
  • 無ければ、錠を取り、tmp/ の中に空の package.json を作って npm install <パッケージ>@<版> を動かし、済んだら名前の付け替えで移す(DES-004 と同じ形)
  • 動かす道具は、入れたパッケージの package.json の bin から選ぶ。1 つならそれ、複数ならパッケージ名(スコープを除く)と同じ名前のもの。どちらでもなければ、選べる名前を示して止まる
  • 動かし方は DES-006 の 3 と同じ

DES-008node list / install / uninstall REQ-006

  • list は cache/node/ のフォルダ名を版の順に並べる。install は DES-004。uninstall は錠を取ってフォルダを消す
  • list --remote は、取り先 https://nodejs.org/dist の index.json を読む。各版の files に、この OS の配布物の名前(macOS arm64 は osx-arm64-tar、macOS x64 は osx-x64-tar、Linux は linux-x64、Windows は win-x64-zip)がある版だけを残す(index.json の中身は 2026-10 の実物で確認: 870 版、version・date・lts(名前か false)・files などを持つ)
  • 結果は標準出力に 1 版 1 行で出す(24.21.0 LTS Krypton (入れてある))。版の前の v は付けない(.node-version にそのまま書けるように)

DES-014add・remove REQ-012

  • nv add は Node を揃え(REQ-002)、npm install --save(--dev なら --save-dev、--exact なら --save-exact)を、プロジェクトの錠(DES-005)を取って動かす。npm の出力は標準エラーへ(DES-012)
  • nv remove は、先に package.json の dependencies・devDependencies・optionalDependencies にその名前があるかを見て、無ければ止まる(npm は無い名前の uninstall を黙って成功させるため)。あれば npm uninstall を動かす
  • どちらも、終わったあと DES-005 の印(package-lock.json の SHA-256 と Node の版)を書き直す。npm が node_modules をロックファイルのとおりにしているので、次の nv run は入れ直さない
  • 却下: package.json を nv が書き換えてから npm install(npm と同じ解決を二重に持つことになる)
