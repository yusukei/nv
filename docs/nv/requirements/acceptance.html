nv 要求仕様

受け入れ条件

確かめは Windows x64 と macOS arm64 の両方で行う。Windows では PowerShell と cmd の両方から打つ。

受け入れ条件

AC-001Node の版の固定 REQ-001

  • .node-version に 24.11.1 と書いたプロジェクトで nv run node --version を打つと、v24.11.1 が出る。PATH にほかの版の Node があっても同じ
  • .node-version が無い、または 24 と書いてあると、何も取らずに止まり、書き方が出る

AC-002Node の取得 REQ-002

  • 置き場にその版が無い状態で nv sync を打つと、置き場にその版ができる。もう一度打つと、取り直さない
  • Windows でも macOS でも、取った Node は ~/.nv/cache の下にあり、~/.nv の外(%LOCALAPPDATA%・~/Library/Caches など)に nv のものができていない
  • 取った配布物が検証値と合わないと、置き場に何もできずに止まり、検証値が合わないと出る
  • 取っている途中で止めると、置き場に壊れた版が残らない(次の nv sync で取り直して動く)
  • 2 つの nv sync を同時に打っても、両方が成功し、置き場の版は 1 つ
  • 公式に直接出られず、プロキシ(HTTPS_PROXY)を通してだけ出られる網で、nv sync が Node を取れる

AC-003sync REQ-003

  • package-lock.json のあるプロジェクトで nv sync を打つと、node_modules がロックファイルのとおりになり、ロックファイルは変わらない
  • package-lock.json が無いと、何も入れずに止まる
  • ~/.npm(Windows は %LOCALAPPDATA%\npm-cache)を消してから nv sync を打つと、npm のキャッシュは ~/.nv/cache/npm にでき、~/.npm などには何もできない

AC-004run REQ-004

  • nv run npm run build が、.node-version の Node と、その版に付いた npm で動く。package.json のスクリプトの中で起きる node も同じ版
  • node_modules を消してから nv run <プロジェクトの依存にある道具> を打つと、先に依存が入り、その道具が動く
  • 依存が揃った状態で nv run node --version を 2 回打つと、2 回目は依存を入れ直さない。package-lock.json を変えると、次の nv run で入れ直す
  • Windows で .cmd の形の道具(node_modules/.bin にあるもの)を、nv run <名前> で動かせる
  • nv run node -e "console.log(process.argv)" "a&b" "*" で、a&b と * が文字のまま届く(PowerShell・cmd・zsh のどれから打っても)
  • echo hi | nv run node -e "process.stdin.pipe(process.stdout)" で hi が出る
  • 動かしたコマンドが 3 で終わると、nv run も 3 で終わる

AC-005x REQ-005

  • プロジェクトの依存に無い道具を nv x <パッケージ>@<版> --version で動かすと、その版が出て、プロジェクトの package.json・package-lock.json・node_modules は変わらない
  • 2 回目は置き場のものを使い、取り直さない
  • 版を latest や 4 と書くと、何もせずに止まる
  • プロジェクトの外で nv x … --node 22.11.0 を打つと、その版の Node で動く。.node-version も --node も無いと、何もせずに止まる。.node-version のあるプロジェクトでは、その版で動く

AC-006Node の版の管理 REQ-006

  • nv node install 22.11.0 のあと nv node list に 22.11.0 が出る。nv node uninstall 22.11.0 のあと出ない
  • nv node list --remote は、系列ごとに最新の版が 1 行ずつ、新しい順に並ぶ。LTS の版には LTS の名前が付き、置き場に入っている版には印が付く。その OS 向けの配布物が無い版は出ない
  • nv node list --remote 24 は 24 系のすべての版、--lts は LTS の版だけ、--all はすべての版を出す

AC-007利用者の環境 REQ-007

  • nv をどう使ったあとも、利用者の PATH・シェルの設定ファイル・グローバルの npm の中身が変わっていない
  • nv sync のあと、新しく開いた端末で node --version を打つと、nv を使う前と同じ結果になる(nv の Node は nv の外に出てこない)

AC-008エージェント用のスキル REQ-008

  • nv install skill のあと、~/.claude/skills/ と ~/.agents/skills/ に nv と wrangler-compose のスキルがあり、どこに入れたかが出る
  • 入れたスキルに、REQ-008 の守らせること(Node・npm・npx を直接打たない、JS は nv run node、Cloudflare の環境は wrangler-compose)が書いてある
  • Claude Code と Codex のそれぞれに、別のプロジェクトで「この JS のスクリプトを動かして」と頼むと、node ではなく nv run node … で動かす(それぞれ新しい会話で 3 回頼み、3 回とも)
  • Claude Code と Codex のそれぞれに、Wrangler の設定を持つプロジェクトで「staging にデプロイして」と頼むと、wrangler deploy ではなく wrangler-compose --env staging up で行う(同じく 3 回とも)
  • ~/.claude の無い PC では、~/.agents/skills/ だけに入り、Claude Code に入れなかったことが出る。Codex の無い PC でも ~/.agents/skills/ には入る
  • nv uninstall skill のあと、nv が入れたスキルが無くなり、どこから消したかが出て、ほかのスキルは変わらない
  • 2 回続けて nv install skill を打っても、スキルは 1 つ(上書き)

AC-009配り方 REQ-009

  • Node も npm も入っていない Windows と macOS で、Release から取った実行ファイルを 1 つのフォルダに置くだけで、nv sync と nv run node --version が動く(インストーラも PATH の書き換えも要らない)
  • 版のタグを push すると、その版の GitHub の Release に、Windows x64・macOS arm64・macOS x64・Linux x64 の nv と wrangler-compose の実行ファイルと検証値の一覧が並ぶ。Linux x64 の nv で nv run node --version が動く

AC-010更新 REQ-010

  • 古い版の nv で nv self update を打つと、最新の版に入れ替わり、nv --version に最新の版が出る。前と後の版が示される
  • nv と同じフォルダに wrangler-compose があると、nv self update のあと wrangler-compose --version も nv と同じ版になる。無ければ wrangler-compose は入らない
  • 最新の版で nv self update を打つと、何も変わらず、最新であると出る
  • nv self update --check は、新しい版があるかを示し、実行ファイルは変わらない
  • 取った実行ファイルが検証値と合わないと、入れ替えずに止まり、いまの nv が動く
  • 取っている途中で止めても、いまの nv が動く
  • Windows で、動いている nv から nv self update を打っても入れ替わる
  • プロキシを通してだけ出られる網で、nv self update が動く
  • スキルを入れてある PC で更新すると、スキルの中身も新しい版のものになる
  • nv self update 以外のコマンドを打っても、GitHub へ通信しない

AC-011表示の言語 REQ-011

  • OS の言語が日本語の macOS と Windows で、.node-version の無いプロジェクトで nv run node -v を打つと、日本語のエラーが出る。nv --help の説明も日本語
  • OS の言語が英語の PC では、同じ操作で英語が出る
  • NV_LANG=en を付けると日本語の PC でも英語、NV_LANG=ja を付けると英語の PC でも日本語が出る
  • Windows の PowerShell と cmd で、日本語のメッセージが化けずに読める
  • nv run npm install の npm の出力は、言語によらず npm のまま出る

AC-012add・remove REQ-012

  • package-lock.json の無いプロジェクトで nv add semver を打つと、package.json の dependencies に semver が入り、package-lock.json ができ、.node-version の Node に付いた npm が使われる
  • nv add --dev typescript@5.6.3 --exact は、devDependencies に "5.6.3"(幅なし)で入る
  • nv add のあとすぐ nv run を打っても、依存を入れ直さない
  • nv remove semver のあと、package.json と package-lock.json から semver が消え、nv run semver は動かない。続けて nv run を打っても依存を入れ直さない
  • 依存に無いパッケージを nv remove すると、何も変わらずに止まる
