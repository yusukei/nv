nv 要求仕様

Node・npm を uv のように扱う道具。

コマンドの名前は nv(利用者の決定)。uv が Python 本体の取得・版の固定・依存の導入・実行を 1 つのコマンドにまとめているのと同じく、Node について同じことをする。 利用者とエージェントは nv だけを打ち、node・npm・npx を直接打たない。Windows でも macOS でも同じ動きをする。

コマンド体系

コマンドすること条項
nv syncNode を揃え、package-lock.json のとおりに依存を入れるREQ-003
nv run <コマンド> [引数…]揃えた Node・npm・node_modules/.bin でコマンドを動かす(足りなければ先に揃える)REQ-004
nv x <パッケージ>@<版> [引数…]
[--node <版>]		プロジェクトに入れずに道具を 1 回動かすREQ-005
nv add <パッケージ>[@版]… [--dev] [--exact]依存を足し、package.json と package-lock.json に書くREQ-012
nv remove <パッケージ>…依存を外し、package.json と package-lock.json から消すREQ-012
nv node list置き場にある Node の版を並べるREQ-006
nv node list --remote [<系列>] [--all] [--lts]入れられる Node の版を並べる(既定は系列ごとの最新)REQ-006
nv node install <版>その版の Node を取るREQ-006
nv node uninstall <版>その版の Node を置き場から消すREQ-006
nv install skillClaude Code と Codex に、nv と wrangler-compose のスキルを入れる(利用者全体)REQ-008
nv uninstall skillnv が入れたスキルを消すREQ-008
nv self update [--check]nv と wrangler-compose を最新の版に入れ替える(--check は調べるだけ)REQ-010

Node の版はプロジェクトの .node-version が決める(REQ-001)。コマンドに版を渡すのは、プロジェクトの外で使う nv x --node と nv node だけ。

決定(利用者)

  • uv のスタイルで使う(別の版の管理の道具(fnm など)を入れさせない)
  • wrangler-compose とは別の道具として作る。同じリポジトリに置く
  • Cloudflare に触れず、Wrangler を自分で動かさない(Wrangler を使わないプロジェクトでも使える)。wrangler-compose は、一緒に配る実行ファイルとスキルとしてだけ扱う
  • 個人の道具として wrangler-compose と 1 つのリポジトリにまとめ、更新(self update)とエージェント用のスキル(install skill)は nv に寄せる。nv が wrangler-compose の分も扱う
  • エージェント用のスキルは Claude Code と Codex に、利用者全体へ入れる。Codex 向けは共有の置き場 ~/.agents/skills/ に常に入れる
  • nv が利用者ごとに持つものは ~/.nv の下に置き、Node と道具の置き場は ~/.nv/cache に統一する(OS ごとに置き場所を変えない)
  • nv が動かす npm のキャッシュも ~/.nv/cache/npm に置き、利用者がほかで使う npm のキャッシュ(~/.npm など)と分け合わない(uv がパッケージのキャッシュを自分で持つのと同じ考え方)
  • GitHub の公開のリポジトリ yusukei/nv(個人)に置き、GitHub Actions で Release に OS ごとの実行ファイルを置く
  • 公開して配るので、更新の機能を持つ

用語

語意味
プロジェクトpackage.json を持つフォルダ。いまいるフォルダから上へたどって最初に見つかるもの
Node の版プロジェクトの .node-version に書いた、24.11.1 のような 3 つの数の版
nv のフォルダ利用者のホームの ~/.nv(Windows は %USERPROFILE%\.nv)。nv が利用者ごとに持つものは、すべてこの下に置く。利用者全体の設定などが要るようになったら、ここに置く
置き場nv が Node と道具を置くフォルダ。どの OS でも ~/.nv/cache

要求

REQ-001Node の版の固定

  • 使う Node の版は、プロジェクトの .node-version の 1 か所で決める(fnm など、ほかの道具も読む書式)
  • 版は 3 つの数で書く(24 や lts のような幅のある書き方は受けない。誰の PC でも同じ版にするため)
  • .node-version が無い・書式が違うときは、何もせずに止まり、書き方を示す

REQ-002Node の取得

  • 決めた版の Node が置き場に無ければ、Node の公式の配布物から取る。取ったものは、配布元の検証値の一覧(SHASUMS256.txt)と照らし、合わなければ使わずに止まる
  • OS と CPU に合う配布物を選ぶ(Windows x64、macOS arm64・x64、Linux x64)
  • 取得や展開の途中で止まっても、壊れた版が置き場に残らない(次に取り直せば動く)
  • 同時に複数の nv が同じ版を取りに行っても、取り合わない
  • 社内のプロキシの設定(HTTPS_PROXY など)に従う

REQ-003sync(依存を揃える)

  • nv sync は、Node を揃え(REQ-002)、その版に付いている npm で、プロジェクトの package-lock.json のとおりに依存を入れる(npm ci)
  • package-lock.json が無ければ、何もせずに止まる(ロックファイルを書き換える導入はしない)
  • nv が動かす npm(nv sync・nv run npm …・nv x)は、キャッシュに ~/.nv/cache/npm を使う(利用者の決定)

REQ-004run(揃えた環境で動かす)

  • nv run <コマンド> [引数…] は、揃えた Node・npm と、プロジェクトの依存に入れた道具(node_modules/.bin)を、利用者の環境にあるほかの Node・npm・道具より優先してコマンドを動かす(nv run node script.js・nv run npm run build・nv run wrangler deploy など)。動かしたコマンドがさらに起こす node・npm も、揃えたものになる
  • 動かす前に、Node が無い・依存が package-lock.json と合っていなければ、先に揃える(REQ-003)。合っていれば入れ直さない(nv run のたびに依存を入れ直して遅くしない)
  • 引数はシェルに解釈させず、そのまま渡す(*・&・| などの記号も文字のまま)。Windows で .cmd などの形のコマンドも、同じ書き方で動く
  • 標準の入出力(標準入力を含む)と終了コードは、動かしたコマンドのものをそのまま返す

REQ-005x(プロジェクトに入れずに道具を動かす)

  • nv x <パッケージ>@<版> [引数…] は、そのパッケージをプロジェクトに入れず、置き場に入れて 1 回動かす(uv の uvx に当たる)
  • 版は 3 つの数で書く。同じパッケージと版は、置き場のものを使い回す
  • Node の版は、プロジェクトの .node-version、無ければ --node <版> で決める。どちらも無ければ止まる

REQ-006Node の版の管理

  • nv node list は、置き場にある Node の版を並べる
  • nv node install <版> は、その版を取る(REQ-002)
  • nv node uninstall <版> は、置き場からその版を消す
  • nv node list --remote は、入れられる Node の版を並べる。その OS 向けの配布物がある版だけを、Node の公式の一覧(REQ-002 と同じ取り先)から出す(利用者の決定)
    • 既定では、大きい版(系列)ごとに最新の版を 1 つずつ、新しい順に出す
    • 系列を指定すると(nv node list --remote 24)、その系列のすべての版を出す。--all はすべての版、--lts は LTS の版だけ
    • 各版に、LTS の名前と、置き場に入っているかの印を付ける

REQ-007利用者の環境に手を出さない

  • 利用者の PATH、シェルの設定、ほかの道具(fnm・Homebrew・グローバルの npm)で入れたものに、何もしない。例外は、利用者が nv install skill / nv uninstall skill を打ったときの、エージェントのスキルの置き場だけ(REQ-008)と、nv self update を打ったときの nv と wrangler-compose の実行ファイルだけ(REQ-010)
  • 揃えた Node は、nv が起動する処理の中だけで使う

REQ-008エージェント用のスキル

  • nv install skill は、コーディング用のエージェント(Claude Code と Codex)に、nv と wrangler-compose の使い方のスキルを入れる。nv uninstall skill は、入れたスキルを消す(nv が入れたもの以外は消さない)
  • 入れる範囲は利用者全体(その PC のすべてのプロジェクトで効く)(利用者の決定)
  • Codex 向けには、利用者全体の共有の置き場 ~/.agents/skills/ に常に入れる(Codex が利用者のスキルを読む場所。OpenAI の資料「Build skills」)。この置き場はほかのエージェントとも共有で、Codex が入っているかは見分けない(利用者の決定)
  • Claude Code 向けには ~/.claude/skills/ に入れる。~/.claude が無い PC(Claude Code が無い)では入れず、入れなかったことを示す
  • スキルは、エージェントに次を守らせる: Node・npm・npx を直接打たず、nv sync・nv run <コマンド>・nv x <パッケージ>@<版> を使う。JS のスクリプトは nv run node <スクリプト> で動かす。依存を足す・外すのは nv add・nv remove。Cloudflare の環境の建てる・下ろす・控える・戻すは、wrangler deploy などを直接打たず wrangler-compose --env <環境名> <操作> で行う
  • スキルの中身は、その版の nv と wrangler-compose の使い方と一致する(nv を更新したら、入れてあるスキルも合わせる。REQ-010)
  • 入れる・消すときに、どのエージェントのどこに入れた・消したかを示す

REQ-009配り方

  • OS ごとの単体の実行ファイルで配る(Windows x64、macOS arm64・x64、Linux x64)。動かすのに Node も npm も要らない
  • GitHub の公開のリポジトリに置き、版のタグを push すると、GitHub Actions が OS ごとに組み、その版の Release に実行ファイルと、その検証値の一覧を置く(利用者の決定)
  • nv と wrangler-compose は同じ版のタグで一緒に組み、同じ Release に並べる(版は 2 つで揃える)
  • 最初の導入は、Release から OS に合う nv(と、使うなら wrangler-compose)を取り、1 つのフォルダに置くだけで済む(インストーラや PATH の書き換えを要さない。PATH に入れるかは利用者が決める)

REQ-010更新

  • nv self update は、GitHub の Release の最新の版を調べ、いまの版より新しければ、OS に合う実行ファイルを取り、Release の検証値の一覧と照らしてから、nv 自身と入れ替える。合わなければ入れ替えずに止まる
  • nv と同じフォルダに wrangler-compose があれば、同じ版の wrangler-compose にも同じ手順で入れ替える(2 つの版がずれない)
  • nv self update --check は、新しい版があるかだけを示し、何も変えない
  • 取得は REQ-002 と同じく社内のプロキシの設定に従う
  • 入れ替える前と後の版を示す。すでに最新なら何もしない
  • 取っている途中や入れ替えの途中で止まっても、いまの nv は動くまま残る(Windows で、動いている実行ファイルを入れ替えられない場合も含む)
  • 入れ替えたあと、エージェントのスキルが入っていれば、新しい版の中身に入れ直す(REQ-008)
  • nv は、利用者が打たない限り、更新を調べに行かない(打ったコマンドのたびに網へ出ない)

REQ-011表示の言語

  • nv が自分で出すメッセージ(進み具合・結果・エラー)と --help の説明は、OS の言語が日本語なら日本語、それ以外は英語で出す(利用者の決定)
  • 環境変数 NV_LANG(ja / en)があれば、OS の言語より優先する(エージェントが出力を読むときなどに言語を固定できる)
  • nv が動かしたコマンド(Node・npm・道具)の出力は、そのまま出す(訳さない)。エージェント用のスキルの中身は英語のまま

REQ-012add・remove(依存を足す・外す)

  • nv add <パッケージ>[@版]… は、固定した Node に付いた npm でパッケージを入れ、package.json と package-lock.json に書く(利用者の決定)
  • --dev で開発用の依存として書く。--exact で版を幅なしで書く
  • 版は幅のある書き方(foo・foo@^1)も受ける(実際の版は package-lock.json が固定する)
  • package-lock.json がまだ無いプロジェクトでは、ここで作る
  • nv remove <パッケージ>… は、固定した Node に付いた npm でパッケージを外し、package.json と package-lock.json から消す(利用者の決定)。依存に無いパッケージを指定したら、何も変えずに止まる
  • 足した・外したあと、次の nv run で依存を入れ直さない(依存が揃っている状態として扱う。REQ-004)

範囲外

  • npm 以外の依存の道具(yarn・pnpm・bun)
  • 依存の版を上げるための専用のコマンド。nv run npm update … で npm に任せる。依存を足す・外すのは nv add・nv remove(REQ-012)
  • グローバルへの導入とシェルへの組み込み(fnm の use や、シムのようなもの)
